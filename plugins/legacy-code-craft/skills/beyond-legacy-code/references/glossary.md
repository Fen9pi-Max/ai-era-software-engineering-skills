# GLOSSARY — 《修改软件的艺术》(Beyond Legacy Code) 共享术语词典

> 来源: candidates/glossary.md(阶段1)→ 阶段3 整理提升。所有能力卡共用本词典的口径。
> 格式: 术语 | 作者的定义(尽量原文) | 与常识用法的差异 | 下游用途

## 核心概念

### 遗留代码 (legacy code)
- **定义**: "因为种种原因,格外难以修正、改进以及使用的代码"(引 Michael Feathers:任何没有测试的代码)。
- **差异**: ≠老代码/前任的代码(与年代无关);≠还在正常运行的代码(不修改就不是问题)。=难修改+缺测试。
- **用途**: 判定"是否遗留"决定是否触发重构(地雷原则),误判会导致去动不该动的代码。

### 名义上的敏捷 (nominal agile)
- **定义**: "采用了在无数的书中描述的实践,却收效甚微的组织"。
- **差异**: ≠敏捷实施不熟练。=有实践之形(站立会/冲刺)无实践之理(消除WIP/清零风险/技术卓越)。
- **用途**: 诊断术语——识别它才知道该补技术实践而非换方法论。

### 用户故事 (user story)
- **定义**: 包含"是什么/为什么/给谁"的一句话(Cockburn:"沟通的保障")。
- **差异**: ≠需求文档简化版;≠用例(用例是多场景的内容,故事是单一场景的标题)。=引发对话的占位符,禁载"如何做"。
- **用途**: `user-story-first` 的产出物;验收测试与拆分的对象。

### 半成品/在制品 (WIP)
- **定义**: "软件的浪费是所有已经开展但尚未完成的任务"。
- **差异**: ≠进行中的正常工作。=已投入未产生客户价值的任务;99%完成的任务风险未知。
- **用途**: `small-batches` 的核心度量对象;利特尔法则的分子。

### 完成三层次 (done / 完整完成 / 完美完成)
- **定义**: 完成=本机可执行;完整完成=已集成;完美完成=已集成+清晰且健壮。
- **差异**: 常识只到第一层;作者说"完成"一律指完美完成。
- **用途**: `continuous-integration` 的 DoD 判级。

### 时间盒子 / 范围盒子 (time box / scope box)
- **定义**: 时间盒子=固定时间周期执行任务;范围盒子=以可简单描述的完整工作(一个故事/功能)为单位。
- **差异**: 时间盒子是训练轮(尼古丁贴片),终点是流式的范围盒子。
- **用途**: `small-batches` 判断团队所处阶段。

### CLEAN 五特质
- **定义**: 内聚(Cohesive)/松散耦合(Loosely Coupled)/封装(Encapsulated)/自主(Assertive)/无冗余(Nonredundant)。
- **差异**: ≠代码风格问题。=可量化结构特质;"自主"与"冗余=意图重复"与一般表述差异最大。
- **用途**: `clean-code-qualities` 的评估维度;全部技术卡的公共语言。

### 有意耦合 / 意外耦合 (intentional / accidental coupling)
- **定义**: "我希望在需要的时候进行耦合"(如退出按钮→退出动作);意外耦合=因低质量代码混入的耦合(Scott Bain 术语)。
- **差异**: ≠松耦合好/紧耦合坏的二分。按意图判定耦合正当性。
- **用途**: 耦合评估的判定口径,防解耦教条化。

### 单元(测试的) (unit)
- **定义**: "单元是指一个行为的单元:一个独立的、可验证的行为"。
- **差异**: ≠方法/类/模块。行为不变则测试不变,即使类/方法重构。
- **用途**: `test-first-tdd`/`behavior-specification-tests` 的地基定义。

### 技术债 (technical debt)
- **定义**: Ward Cunningham 的比喻:欠考虑的代码如债务累积利息(1.7万美元只还最低额需93年/18.4万)。
- **差异**: ≠烂代码的婉称。=带利息的债务,可战略性暂时持有,装作不存在则滚到不可偿付。
- **用途**: `legacy-refactoring` 的时机决策与对管理层论证框架。

### 图钉测试 (pinning test)
- **定义**: 粗粒度测试,覆盖成百上千行代码的整体行为,每次修改后回验。
- **差异**: ≠单元测试。=遗留代码抢救的脚手架/行为锁定锚点。
- **用途**: `legacy-refactoring` 步骤2。

### 系统扼杀 (strangler application)
- **定义**: 新服务包裹老服务→逐块替换→老服务只剩外壳(Fowler 2004)。
- **差异**: ≠重写;≠普通重构。=渐进替换,系统全程可用。
- **用途**: `legacy-refactoring` 大粒度替换策略。

### 抽象分支 (branch by abstraction)
- **定义**: 提取接口+新旧实现并存+功能开关切换(Fowler)。
- **差异**: ≠版本分支——它是**消除**版本分支的主干技术。
- **用途**: `legacy-refactoring` 与 `continuous-integration` 的交叉技法。

### 意图导向编程 (programming by intention)
- **定义**: 公共方法只做同层委托("读起来就像一段脚本或一个菜单"),实现下沉私有方法。
- **差异**: ≠用注释表达意图。=保持单一抽象层次的代码组织法。
- **用途**: `design-last` 核心技法。

### 圈复杂度 (cyclomatic complexity)
- **定义**: 代码路径数(McCabe 1976);一个if=2,独立条件相乘;"一个方法所需的最少测试数量等于其圈复杂度"。
- **差异**: ≠代码行数。=分支路径数=测试数下界。
- **用途**: `design-last` 的量化判据。

### 守破离 (shu-ha-ri)
- **定义**: 合气道精通三阶段:守=照规则做,破=理解原理,离=融会创变。
- **差异**: ≠一般初中高级。技艺学习的完整弧线(毕加索先精规则再破规则)。
- **用途**: `book/overview.md` 元框架;解释实践学习曲线。

### 前构 (prefactoring)
- **定义**: 精通重构后"一开始就写出优质的代码"(Ken Pugh 书名)。
- **差异**: ≠预先设计。=重构经验内化的副产品。
- **用途**: 澄清"重构不是写烂代码的借口"。

## 辅助术语

### 测试感染者 (test infected)
Erich Gamma 造词:体验过 TDD 价值后"非得使用TDD不可"的开发者。TDD 推广的心理里程碑。

### 仪表法 (instrumentation)
用意图明显的变量(personAge 而非 21)与见名知意 helper 组织测试,让测试读如标准文档。`behavior-specification-tests` 的技法。

### 镀金 (gold plating)
无验收标准约束的投机性过度开发("近半数功能从未被使用"的直接原因)。

### 快乐路径 (happy path)
假设不出错的最顺利分支;边界情况是它的分支,须进验收测试("死之蓝屏"警示)。

### 穿刺 (spike)
两个以上开发者+时间盒子+预设问题清单的未知研究机制;结束即解散。

### 群战 / 围攻 (swarm / mob programming)
群战=小组同时攻坚同一问题;围攻=全团队+双投影仪+轮流驾驶(Woody Zuill),像蚁群分解食物。

### 最小可市场化功能集 (MMF)
"一个产品若想可用并且有价值所必需的东西";范围控制的锚点;待办排顺序而非优先级。

### 铁公鸡 (deadbeat, 信用卡业行话反用)
账单一到就全额还款、不给信用卡公司赚利息的人——作者希望你对技术债也如此。

### 测试引入的损伤 (test damage)
过度测试或依赖实现的测试最终"成了负担而不是资源"——TDD 失败的主因,"TDD已死"论战针对的形态。

### 完美完成的反义: 99% 完成
"一个完成度99%的任务没有多大价值,因为其风险未知"——薛定谔的猫状态,只有完整集成才能打开盒子。
