# 决策规则速查 — 修改软件的艺术：构建易维护代码的9条最佳实践（Beyond Legacy Code）

| 能力 | 一句话规则 |
|---|---|
| 在问如何做之前先问做什么、为什么做、给谁做 | 把需求压成"作为谁/希望什么/以便为什么"一句话+二值可判的验收标准, 实现细节一个字不写。 |
| 小批次构建:拆分故事、限制半成品、控制范围 | 故事过大先判型(复合→按组件拆;复杂→分离已知未知), 任务≈4理想小时, 完成一个再领一个, 压力来了砍范围不砍质量。 |
| 持续集成:项目的心跳 | 版本库管理构建所需的一切, 一键构建分钟级, 主干+功能开关替分支, 构建失败立即修——完成=完整集成+清晰健壮。 |
| 协作:结对编程与回顾会议 | 结对=驾驶员+领航员实时交流、5-30分钟轮换、随机换搭档; 回顾会责怪流程不责怪人, 5个为什么找根因, 选2%级小改进。 |
| CLEAN 五特质:评估并改善代码质量 | 用五个可判定特质评代码——内聚(难命名=职责不清)、意外耦合该消除、默认封装必要时暴露、行为放在它依赖的数据处、冗余=意图的重复; 可测试性是综合标尺。 |
| 测试先行:红绿重构循环 | 先写表达意图的失败测试(那是假设不是测试)→存根→确认红条→写刚好让它通过的代码→重构; 单元=行为单元, 不是代码单元。 |
| 用测试描述行为:判定测试数量与唯一性 | 测试数量由行为结构决定: 线性区间恰3断言(下界-1/首合法/上界+1), 每个测试的失败原因必须唯一; bug=缺失的测试, 先写重现它的失败测试。 |
| 最后实现设计:演化式设计与意图导向编程 | 健壮性设计推迟到有运行代码+测试之后: 公共方法只做同层委托(意图导向), 创建进工厂使用靠多态, 圈复杂度=最少测试数, 第2-3个用例到齐再泛化。 |
| 重构遗留代码:安全下手的程序 | 没坏别修(地雷原则); 要动就先建防护网(图钉测试→依赖注入→细测试); 加功能=两步走: 先重构出容纳空间, 再只添加代码; 技术债做铁公鸡。 |
| 度量软件开发:价值导向的7个策略 | 用客户价值度量开发(价值时间/编码占比/缺陷密度/发现缺陷时间/功能价值/未交付损失/回路效率); 速度与代码行数是局部优化, 进黑名单。 |

> 速查只给结论；需要原文依据、案例或反例时读对应能力卡。
