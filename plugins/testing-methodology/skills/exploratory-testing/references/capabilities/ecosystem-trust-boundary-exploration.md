# 生态系统图与信任边界探索

## R（原文摘引）
> 系统的生态系统包括软件的所处环境、所有入口和所有外部依赖。（第9章9.1）

> 找出信任边界之后，你作为一名探索者的任务就是要破坏信任。（第9章9.2）

## I（解释）
**三步画图**（语境图+部署图 mash-up，GML：方框+线条+标注）：
1. 画接口：中央大圆=系统边界；外面放用户（终端/管理员）及其 UI；加公共接口（API/监听器/消息队列）。
2. 画外部依赖：支付网关、SSO、云存储、外部数据源、数据源与接收端系统。
3. 填内部：部署组件 + 全部数据落点（数据库、配置文件、用户上传文件、日志、临时文件）——按探索相关性取舍，避免分析麻痹（"所有模型都有错，但有一部分是有用的"）。
**信任边界**：凡是系统无法确定对端按规矩办事的地方——公共接口、数据库（技术支持会直改数据！）、文件系统、网络连接。
**如果的话**：拿图当地图逐连接提问并动手做：
- 网络连接：断开、防火墙隔离、限速（netem）；
- 文件：删除、损坏内容、空文件覆盖、超大、远程驱动器、只读、去权限、被他进程锁住、磁盘塞满。
**跟随数据**（生态版）：非法数据从任一接口进入，沿图追它在数据库/管理界面/网关/日志每个落点的副作用（注入攻击要查所有出口不止 UI）。

## A1（原书案例）
- 信用卡支付 Web 系统：两类用户接口+支付网关外部依赖+Rails 应用+关系库+文件系统图片存储。
- 费曼指着蓝图问"如果这个阀门堵住了会怎样？"——工程师们顺着蓝图找出一处真实疏漏。
- 90 年代菜单系统：会计用户用字处理软件打开并保存纯文本菜单文件致其损坏，用户全体功能瘫痪——文件看似在信任边界内其实不是；补救=只读权限锁文件。

## A2（情境应用）
1. 对被测系统画图：三步走，先粗后细，画完即分享给团队补漏。
2. 圈出全部信任边界（公共接口/DB/文件/网络）。
3. 对图上每条连线至少做一次"如果的话"实操（断/慢/删/锁）。
4. 注入一条带特殊字符的数据，跟随它走完所有落点核对副作用。

## E（评测）
- 输入：任一多依赖系统描述（如"Web 应用+支付网关+对象存储"）。
- 输出：生态系统图（接口/外部依赖/内部数据落点齐备）+ 每连接一条故障注入动作 + 一条跟随数据路径。
- 通过标准：数据落点含配置与日志；故障注入含网络与文件两类；信任边界逐一点名。

## B（边界）
画图服务于探索，不追求部署文档级精确；需求期的"如果的话"预防用法见 requirements-exploration。依据第9章。
