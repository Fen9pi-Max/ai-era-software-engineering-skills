# 噩梦头条工作坊

## R（原文摘引）
> 你已经准备好开始这一天…一个耸人听闻的头条标题映入眼帘…这吓死人的头版头条似乎跟你们的软件很有关系。现在说说这个头条是什么？（第2章2.5）

## I（解释）
五步群体工作坊（纸+记号笔）：
1. **搭台**：让参与者想象早晨看到的与自家软件相关的灾难头条，暂停让人入戏。
2. **收集头条**：各自写在纸上并朗读；鼓励润色细节、玩得开心（"收到 827 个花园精灵，男子惊呼：可我只订了一个！"）。
3. **选一个大风险**：挑合理、相关、值得讨论的；无共识用累积投票法（每人三票可自由分配，圆点贴纸统计）。
4. **头脑风暴原因**：选中头条贴白板顶，问"哪些原因可能导致此问题？"写大卡（无效输入/浏览器刷新返回/多次点击提交/集成问题）。
5. **提炼章程**：分 2–3 人小组，自选原因写出章程（"探索购物车与仓库系统集成，使用数量和商品的变化，以图发现订单履行出错的方法"）。
价值：把开发/分析/产品从创造视角切换到"哪里会出问题"；多视角头脑风暴产出远超单人；也是干系人风险共识工具（呼应第5章"风险"神谕）。

## A1（原书案例）
- 购物车四条示例头条：多收 58% 附加费、827 个花园精灵、已付未交、信用卡信息被窃。
- 由"827 个精灵"导出的三条章程：数量修改×输入变化/浏览器动作×采购流/购物车-仓库集成×数量与商品变化。

## A2（情境应用）
1. 组 4–8 人跨职能小组，60–90 分钟，人手纸笔。
2. 严格按五步走，第 3 步准备三色圆点贴纸做累积投票。
3. 产出的章程直接入章程池并按 charter-session-design 校准价值。
4. 季度或大版本前各办一次，对比历次头条识别 recurring 恐惧。

## E（评测）
- 输入：任一产品/团队描述。
- 输出：头条清单（每人 ≥1 条）→投票选出风险→原因清单（≥6）→章程（≥3 条，三段式）。
- 通过标准：章程均含目标/资源/信息三段且能追溯到具体原因；头条覆盖财务/安全/声誉中至少两类风险。

## B（边界）
单人也可行（自问自答）但价值主要在群体多视角；不替代正式风险评估模型。依据第2章2.5。
