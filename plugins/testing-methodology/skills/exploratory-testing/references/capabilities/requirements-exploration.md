# 探索需求：如果的话与积极阅读

## R（原文摘引）
> 花几分钟探索每一个想法的边缘地带，质疑那些假设…这样能避免多达数周的无谓返工。（第12章12.1）

> 我知道，只要能把 Jim 和 Carla 聚起来跟我一起讨论测试，它必然就会变成一个需求会议。（第12章12.1）

## I（解释）
**进入会议**：被排除在外就"渗入"（带上饼干）或开"测试评审会"把各方拉到同一房间——对着具体用例在白板预演，Jim 式期待与 Carla 式实现的鸿沟当场显形（一对一传话=各说各话，同一特性实现三遍的教训）。
**会上做三件事**：
1. **发现关键价值**：问干系人软件要贡献的核心价值、电梯游说、其他功能全坏时什么必须能转；留意 "-ilities"（可靠性/可伸缩性/精确性）质量标准。
2. **问"如果的话"**：用户做了不该做的（已验证态登录/输错密码）？必需资源不可达（配置缺失/被锁/损坏）？输入与预期不同（记录超上限/XML 缺必备节点）？——即席设计测试场景的能力需练习。
3. **记录章程 + 校准**：把"使用"部分（交互特性/数据集/关键配置/角色）与"以图发现"部分（绝不始终/质量标准问题/干系人担忧）当场写成章程，并问"这些信息你要不要知道？"校准价值。
**调整期望值**：程序员说"没人说过要处理非法 HTML！"——探索发现的新期待=变相加需求；早明确范围，别在发布前争论范围蔓延。
**积极阅读**（文档场景）：边读边质问（边界陈述找违反侧）；按输入/处理/输出/问题四区做笔记，哪个区笔记稀薄就多问；把文字段落转成状态图/语境图（客户端与服务器端程序员对协议理解不同=bug 藏身处）。

## A1（原书案例）
- Jim&Carla：A/B 测试特性两度返工，测试评审会上 Carla 说出"你做不到"——三方同房才发现根本误解。
- HTML 解析器：作者持续报非法 HTML bug，程序员爆发"从来没人说过要处理非法 HTML"——期待未对齐即范围之争。

## A2（情境应用）
1. 下次需求会带便利贴：每听到依赖/不确定/"我得想想"就写一条章程。
2. 对每个 happy path 陈述配一个"如果的话"问题。
3. 会末问："我把这些担忧记为探测章程，你们觉得值得探索吗？"
4. 读规格文档时开四区笔记，读完检查哪区最薄；给关键流程画状态图/语境图并对照文字找矛盾。

## E（评测）
- 输入：一份需求描述或讨论会场景。
- 输出：≥5 个"如果的话"问题（分属用户行为/资源/输入三类）+ ≥3 条当场章程 + 期望值确认话术。
- 通过标准：章程含"以图发现"的信息类型；问题无一条可用 happy path 回答。

## B（边界）
判定会上答案对错用 oracle-strategies；章程写法见 charter-session-design；本卡不产出实现级测试用例。依据第12章。
