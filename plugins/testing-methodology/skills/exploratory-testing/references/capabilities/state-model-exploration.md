# 状态建模与转换探索

## R（原文摘引）
> 有没有什么事情是我现在可以做但之前不可以做的？…有没有什么事情是我现在不可以做但之前可以做的？…我现在所采取的行动是否产生了和之前不同的结果？（第8章8.1 Alan Jorgensen 三问）

> 状态表格则提示你要思考，在预期转换的边界之外触发事件时，会发生些什么。（第8章8.4）

## I（解释）
**找状态**：三问探状态 + "当"字诀（"当系统正在导入数据的时候…"=状态）。登录例：已登出→验证中（短暂过渡态）→已登入。**找事件**四类：用户操作、外部产生（目录内容变化）、系统产生（后台导入/验证完成）、时间流逝（超时、每日备份）。
**画图策略**：专注一个目标（一个功能/一个实体生命周期，如缺陷的新建/已分配/已修复/已关闭）；确定一个角度（呼叫者 vs 通话）；调抽象层级（窄目标画细中间态，大目标打包成"启动"）。
**探索模型**四法：
1. **所有途径**：找齐状态 A→B 的每种机制（开→关：正常关闭/杀进程/超时/看门狗重启）。审计线索案例：只有单条编辑入日志，批量更新不留痕。
2. **干扰**：在每个状态触发意外事件——点取消、登出、会话超时、杀进程、合上屏幕、断网；干扰后三问：响应符合预期？恢复正常？数据丢失损坏？
3. **变量重提**：前置状态、进入机制、处于该状态的次数、事件发生次数、循环次数、停留时长（Therac-25 的第 256 次）。
4. **改变呈现**：状态图→状态×事件表格，？？？单元格=未探索转换，专门设计试验填空（闹钟：设定时间恰等于当前时间会响吗？）。
关注可观察行为而非实现细节，从外部视角建模全栈。

## A1（原书案例）
- 登录流程：已登出/验证中（旋转状态条即中间态证据）/已登入。
- 闹钟状态表格：关闭/设置/已设定/响铃/重响 × 事件矩阵，多处 ？？？ 待探。
- 审计线索：批量更新绕过日志——"所有途径"真实战果。
- Therac-25：设置例程每 256 次运行跳过安全检查——"系统曾处于此状态的次数"是变量。

## A2（情境应用）
1. 选定一个工作流（如"订单支付"），边操作边用三问+"当"字诀记录状态与触发事件。
2. 画状态图；再转成表格，标出每个已知转换，留 ？？？ 于未知格。
3. 对每个 ？？？ 设计一次试验；对每个状态执行一次干扰（取消/登出/断网/超时）并核对恢复与数据。
4. 数状态相关变量：进入次数、停留时长、循环次数，各做一次极值。
5. 遇到间歇缺陷，先给失效区域画状态图找短暂中间态。

## E（评测）
- 输入：任一有明确工作流的系统描述（登录/购物结算/文档审批）。
- 输出：状态图（≥5 状态、≥8 转换）+ 状态表格（含 ≥5 个 ？？？ 单元格）+ 干扰试验清单（每状态 ≥1 条）。
- 通过标准：表格覆盖图中全部状态×核心事件；每个 ？？？ 对应一条可执行试验；干扰清单含时间类事件（超时/闲置）。
