# 遗留系统侦察与干系人采访

## R（原文摘引）
> 侦察探测会话结束时，你会更清楚需要进行探索的范围…你或多或少都能了解一些系统各部分如何协同运转的情况。（第11章11.1）

> 你们组使用计费系统的情况有哪些是我应该知道的？（第11章11.3 反例问法）

## I（解释）
**侦察探测会话**（Bach 兄弟命名）：目标是系统地图——①生态系统与接触点（连接到哪/用什么资源/公共与私有接口）②变量（输入输出/配置/顺序/时机/数据属性）③明显漏洞与潜在风险。过关标准：能轻松回答——它能做什么？输入输出在哪？简单序列与对应结果？环境配置如何影响输出？有无绕开公共接口的办法（隐藏配置/直连存储/直达组件）？怎样触发错误状况？答不出就再来一轮。可参考 Bach"轻松按钮"视频十多种技巧（声明测试/文档评审/产品分析/实境测试/鞋测）。
**干系人采访**：名单=付费者/技术支持/维护程序员/业务用户/产品经理。问题三要素：①设定上下文（我为何来）②提供已知概况（我已发现 X 与 Y 链接）③特定开放式问题（你们组如何与订单/发票/支付历史交互？）——对比"有哪些是我应该知道的"这种无从答起的问题。记录新能力与探索答不了的问题。
**选择技术**：时间敏感→状态；顺序可变/面向用户→顺序交互；数据密集→实体 CRUD；广泛交互→生态系统。
**轻量记录**：白板画关键模型拍照上维基（半小时发布见解）；规则类用实例表格（可上 FitNesse/Cucumber/Robot 自动化）；挑核心冒烟/回归短清单。

## A1（原书案例）
- Scrabble Flash 课堂：15 分钟各自侦察后共享，30 分钟全房对系统有坚实理解——独自探索需数小时。
- 计费系统：好问法（上下文+已知+定向开放式）vs 坏问法（全开放）对比。
- 后台监控程序（同章 11.6）：侦察之后才谈得上采访与排障。

## A2（情境应用）
1. 接手未知系统第一小时：开 1–2 个 60 分钟侦察会话，产出生态系统草图+变量清单+章程清单。
2. 用过关 8 问自检，答不出的作为下一会话目标。
3. 列干系人名单，每人准备一个三要素问题，快速闲聊式开始。
4. 按系统特征（时间/数据/交互/集成）给后续会话选 2–3 项技术。
5. 所有发现按三格式沉淀：图拍照上维基/规则表格化/冒烟清单。

## E（评测）
- 输入：一个无文档遗留系统描述（技术栈+大致功能+已知痛点）。
- 输出：侦察会话计划 + 生态系统草图要素清单 + 干系人采访问题集（每人三要素）+ 技术选择及理由。
- 通过标准：8 个过关问题均有获取途径（已答或列为会话目标）；采访问题无纯开放式裸问。

## B（边界）
系统内间歇缺陷排障见 intermittent-bug-hunting；图的画法细节见 ecosystem-trust-boundary-exploration；不产出正式架构文档。依据第11章。
