# BOOK_OVERVIEW — 《探索吧！深入理解探索式软件测试》(Explore It!)

- 作者: Elisabeth Hendrickson；译者: 徐毅；机械工业出版社 2014（原书 Pragmatic Bookshelf 2013）
- 来源文本: 探索吧！深入理解探索式软件测试.epub（19 个 xhtml 章节全文转写, 约 9.6 万字）

## Adler 第一步: 结构（这本书在讲什么, 怎么组织的）

全书回答一个问题: **如何用系统化的调查（探索）发现软件的风险, 与"检查"互补构成完整测试**。

三部分:
1. **奠定基础**（第1–5章）: 测试=检查+探索 等式; 探测章程（目标/资源/信息 三段模板）; 观察细节（无意视盲、可测试性=可视性+控制）; 识别变量（明显/微妙/可间接访问三类, Therac-25/阿丽亚娜5/勇气号三大案例）; 评估结果（绝不和始终、替代资源、近似神谕）。
2. **增加维度**（第6–9章）: 改变顺序和交互（名词动词、随机导航、角色人物）; 实体关系与 CRUD; 状态建模（状态图+状态表格+干扰+所有途径）; 生态系统图（信任边界、"如果的话"、跟随数据）。
3. **结合场景**（第10–13章）: 无用户接口探索（API/语言/Web服务/细究Bug）; 现存系统（侦察会话、干系人采访、不可重现Bug）; 探索需求（如果的话、积极阅读、调整期望值）; 整合（早探索多探索、结对、流程反馈、估算、停止标准、汇报）。
- 附录1: 结对探索作为面试手段; 附录2: 测试启发法速查表（通用+Web）。

## Adler 第二步: 解释（核心论点）

- 已测试 = 已检查 + 已探索; 预先设计的测试是"绊线网", 探索侦察网外区域。
- 探索式测试 = 同时设计测试和执行测试以学习系统, 根据前一个试验的洞察选择下一个试验（设计/执行/学习/指导四要素）。
- 用限时探测会话（SBTM）组织: 会话前定章程, 会话中记录, 会话后汇报。
- 探索不是漫无目的的瞎玩: 章程给方向, 启发法给变化维度, 观察给证据, 神谕给判断。
- 变化（variation）是发现惊喜的手段; 变量是变化的原子单元, 找到变量→用启发法改变它。
- 探索适用于任何接口（GUI/API/批处理/语言/服务）和任何角色（测试/开发/分析）, 贯穿需求→开发→发布全程。

## Adler 第三步: 批判（真实性与局限）

- 作者是探索式测试领域公认专家（Gordon Pask 奖）, 方法论有 James Bach/Cem Kaner 脉络支撑, 案例真实（Therac-25、阿丽亚娜5 为公开事故报告）。
- 局限: 不覆盖"检查"侧（自动化回归/脚本化测试设计细节）; 无度量的覆盖模型, 停止标准偏主观; 案例多为叙述性, 需要读者自行在自己的系统上练习。

## Adler 第四步: 应用（读者拿它做什么）

- 为某个特性写探测章程并执行时间盒会话;
- 面对不熟悉的系统: 侦察会话+生态系统图+干系人采访;
- 面对不可重现Bug: 嫌疑变量清单+状态模型+协作;
- 需求评审会: "如果的话"问题+当场起草章程;
- 日常探索: 启发法速查表作为变化发生器。

## 原书关键任务清单（覆盖审计基准）

1. 制定探测章程 / 规划探测会话
2. 识别并操纵变量（含微妙变量）
3. 观察细节 / 提高可测试性
4. 判定观察到的行为是否正确（神谕）
5. 改变顺序和交互
6. 实体关系 + CRUD 探索
7. 状态建模与转换探索
8. 生态系统 / 信任边界 / 依赖故障
9. 无 UI 系统（API/Web服务）探索
10. 探索现存（遗留）系统 / 不可重现Bug
11. 探索需求 / 积极阅读
12. 把探索整合进开发流程（估算/停止标准/汇报/结对）
