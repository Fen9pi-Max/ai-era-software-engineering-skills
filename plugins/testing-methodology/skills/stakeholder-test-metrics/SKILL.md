# 测试干系人满意与度量体系

## R（原文摘引）
> 走向测试之美的第一步，确定谁是你的测试利益相关者。（第2章）

> 与其去定一个神奇的数字，你真正需要的是100%的失败调研。（第8章）

## I（解释）
**干系人识别**：列出内部（测试同事/主管）与外部（开发、架构、营销、PM、支持、销售、高管、股东、监管、用户、供应商、客户）干系人；每方标注 支持/中立/敌意（反利益相关者如被替代系统维护者），为中立方与反对方制定应对策略。
**三维评价**：有效（满足目标）/高效（资源价值最大化）/优雅（重压之下不失风度）——执行前与各方对齐定义，避免"测试以发现最多缺陷自评、经理以覆盖评价"的冲突。
**度量公式**（用 GQM 构建：目标→问题→指标）：
- DDP = 测试发现缺陷/(测试+产品发现)×100%；基准：独立系统测试≈85%、内部系统≈95%+；严重缺陷 DDP 应接近 100%
- Test ROI =（节省的外部故障成本−测试投资）/测试投资；ACPB（产品中缺陷成本）常为 ACTB 的 2–10 倍
- RTA 回归自动化百分比（标杆≈90%）/ RRC 回归风险覆盖率（自动化增时至少不降）/ ART 加速比=(手工时间−自动时间)/手工时间

## A1（原书案例）
Rex Black 咨询实践中用四步法（识别干系人→了解期望→外在美指标→内在美指标）改善客户测试；Lisa Crispin 团队用迭代速度与"随时可发布"验证测试价值；黑天鹅原则用于回归取舍。

## A2（情境应用）
建立/改进测试度量时：
1. 画干系人表（角色×态度×最关心指标）；
2. 与每方确认"有效/高效"的操作定义；
3. 按 GQM 选 2-4 个指标起步（DDP+RTA 最常用）；
4. 定义数据来源与统计周期，出基线→设目标→定期评审；
5. 冲突场景先回干系人定义再调指标。

## E（评测）
- 输入：项目背景（发布方式、测试团队规模、历史缺陷数据可用性）。
- 输出：干系人表 + 指标方案（公式+数据源+基线建议）。
- 通过标准：指标与干系人关注点一一对应；DDP 分母定义正确；含至少一个内在美指标。

## B（边界）
度量可能被误解/被博弈，须配套解读；数据不足时先建缺陷逃逸记录再算 DDP；不替代管理层沟通本身。
