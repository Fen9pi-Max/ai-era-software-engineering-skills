# 实体关系与 CRUD 探索

## R（原文摘引）
> 只要寻找可以创建的事物，就能很容易地识别出实体来。（第7章7.1）

> 删除一些有很多依赖的事物会怎样？那些被依赖实体是否也会被删除，或者会受到任何影响呢？（第7章7.2）

## I（解释）
**识别实体**：找可创建之物（菜单"新建"/API 构建器）；隐蔽实体——会话（登入创建、登出销毁，有持续时间与 IP 属性）、GUI 表单背后创建/更新的记录、以图形方式呈现的属性（位置/大小/颜色）提示的实体。列属性；属性可能本身也是实体（邮件地址→联系人）。
**画关系**：ERD，"有个…"句式找依赖（账户**有**首要联系人；结算单**有**多笔交易）；多对多需中间实体（供应商↔条项）。
**CRUD 启发法**四组合：
1. **属性值变化 × CRUD**：创建时全填可选字段→清空→更新（可选数据无法清除是常见失常）；URL 漏 http:// 看似保存实未保存。
2. **零/单/多依赖 × CRUD**：创建无依赖实体（无供应商的条项，挑战业务约束）；删除有多个依赖的父实体（删供应商后查条项=丑陋堆栈跟踪）；更新换依赖。
3. **多路径 CRUD**：菜单新建 vs 另存为 vs 副本 vs 撤销重做 vs 副作用（库存低于阈值自动生成订单——走的可能是不同工作流）；比较不同路径产物属性差异。
4. **跟随数据**：实体出现在搜索/报表/最近文档列表/日志等每个视图，改动后在所有视图核对一致性与副作用（删文档后"最近文档"还列出它吗？还能打开吗？）。

## A1（原书案例）
- 库存系统：删供应商后所有依赖条项不可见，任何查看尝试抛堆栈跟踪。
- URL 漏 http://：软件"看似保存了数据，事实上并没有"。
- 作者旧地址公寓房间号一直跟着邮件——"可选数据无法清除"在现实与软件中同构。
- 自动生成的订单与用户创建的订单经历不同工作流——副作用路径是富矿。

## A2（情境应用）
1. 列实体清单：从"新建"入口+表单+隐蔽线索（会话/配置/日志记录）找全，每个标 3–5 属性。
2. 画 ERD 标关系基数（1:1/1:N/M:N）。
3. 生成试验矩阵：每个核心实体 × CRUD × {0,1,多}依赖 + 属性值极值。
4. 对每个"有依赖"的删除试验，事后去所有视图（搜索/报表/列表）验证。
5. 找多路径：同一创建/更新有几种入口（含副作用与撤销），对比产物。

## E（评测）
- 输入：任一数据密集系统描述（如"项目-任务-成员管理"）。
- 输出：实体清单（≥4，含 ≥1 隐蔽实体）+ ERD + CRUD 试验矩阵（≥15 条，含删父实体与清空可选字段两类必选项）。
- 通过标准：删除试验均指定"随后在哪些视图核对"；矩阵中 0 依赖与多依赖情形成对出现。

## B（边界）
跨系统边界的跟随数据见 ecosystem-trust-boundary-exploration；实体生命周期状态（已分配/已关闭）视角见 state-model-exploration。依据第7章。
