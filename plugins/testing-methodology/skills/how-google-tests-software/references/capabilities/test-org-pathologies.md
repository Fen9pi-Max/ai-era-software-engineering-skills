# 测试组织四大缺陷诊断与转型

## R（原文摘引）

> "测试成了开发的拐杖。我们越不让开发考虑测试的问题，把测试变得越简单，开发就越来越不会去做测试。当测试也成为一种服务，能让开发想都不想的时候，那他们就会真的什么也不想了。"（第5章 5.1）

> "测试的价值是在于测试的动作，而不是测试产物。……所有测试产物的价值，在于它们对代码的影响，进而通过产品来体现。"（第5章 5.1）

> "是谁在做测试并不重要，关键是进行了测试。内部试用者、可信赖的测试者、众包测试者，以及早期用户都可能比测试工程师更容易发现bug。实际上，让TE做的测试越少，支持其他人做的测试越多，效果就越好。"（第5章 5.1）

## I（解释）

这是作者对自己所在组织（Google 测试体系）的病理诊断 + 转型推测，全书唯一"自我批判"章节。方法骨架是一张"症状 → 缺陷 → 转型指向"的诊断表：

**缺陷一：测试成开发的拐杖。** 症状：开发提交前从不跑测试、测试团队越扩越大而 bug 不见降、线上问题第一响应人是测试。机理：测试像修草坪服务，太好用就会被"想都不想"地外包出去；独立测试部门加重"质量是别的部门的问题"，出问题时责任轻易推给测试。转型指向：SET 并入开发，测试代码成为一等公民。

**缺陷二：角色认同压倒产品认同。** 症状：工程师自我介绍用职位而非产品（"我是测试"而不是"我在为 Chrome 工作"）；会议纠缠"这是测试的事还是开发的事"。机理：角色成为身份来源后，维护角色边界比做好产品更重要，而用户爱上的是产品，不是开发流程。转型指向：以产品为认同与组织单位。

**缺陷三：崇拜测试产物胜过软件本身。** 症状：年度评审以 bug 数、用例数论英雄；用例库只增不减；团队忙于"维护测试资产"而非推动代码质量。机理：产物可见可统计、动作不可见，考核机制天然偏向可数之物。转型指向：轻文档重行动——ACC 矩阵、10 分钟测试计划正是针对此缺陷的解药。

**缺陷四：谁做测试不重要。** 症状：上线后首批 bug 总是用户先发现；测试编制永远"人手不够"。机理：产品经最严格测试发布后，用户几乎必然发现漏测——TE 只能想象自己是用户，dogfooder 就是真实用户。转型指向：经营内部试用者、可信测试者、众包与早期用户这些"近于免费的测试资源"。

**两个转型机制**（把诊断变成人事动作，而非口号）：
1. SET 方向——测试特性当一等公民：把可测试性、可靠性、可调试性当作与 UI 等同的产品特性，由 PM 管理、软件工程师编写；最佳人事安排是测试特性由团队**新成员**负责——测试特性贯穿产品从 UI 到 API，负责它就是学习产品设计与架构的最佳热身项目，且测试代码不发布，新人不会因影响用户的 bug 承压。人员轮换使所有开发者逐渐真正理解测试。
2. TE 方向——转测试设计师：少量测试设计师规划测试范围、风险热图、漫游路线；组织内部试用者/可信测试者/早期用户/众包执行；评估覆盖率、计算风险影响、确保发现的问题不断减少并调整测试活动；识别安全/隐私/性能等专业需求并安排众包。不写用例、不执行测试（最低限度）。

## A1（原书案例 / 合成演练）

**c29：Google+ 最好的 bug 来自内部试用者。** 三位作者在 Google+ 上亲历：许多最好的 bug 发现者是团队以外的 Google 员工试用者（dogfooder）。"我们想象自己是用户，而内部试用者就是真实的用户！"——这条第一手观察直接支撑缺陷四的诊断，也是 TE 转型测试设计师（组织免费测试资源）的现实依据。

**修草坪类比（原书，缺陷一的机理模型）。** 坐在沙发里看电视时有人来修草坪，服务太轻松以至于"想都不想"就外包了；更糟的是草坪出问题时，责任轻易推给外包公司。测试被做成"送上门的服务"之日，就是开发停止思考质量之时——"测试应该需要一点痛苦，需要开发人员费点心思。"

**合成演练：某公司"独立 QA 部门 30 人、开发从不写测试、测试计划数百页没人看"。** 诊断：缺陷一（测试是太好用的服务）+ 缺陷二（角色与产品割裂）+ 缺陷三（崇拜产物：数百页计划即证据）。处方：测试特性转为产品特性由开发新人负责（热身项目机制）；测试人员转测试设计师，输出风险热图与漫游路线并组织内部试用；数百页计划替换为 ACC 矩阵。

## A2（情境应用）

**触发场景**：
- 管理层在讨论"测试团队要不要独立 / QA 部门要不要拆掉 / 测试要不要并入开发"
- 开发长期不写测试，测试团队疲于兜底、越扩越大，bug 却不见下降
- 测试团队价值被质疑："你们到底产出什么？"；考核只看 bug 数、用例数
- 上线后漏测 bug 频繁由用户先发现，测试团队疲于救火与背锅
- 测试工程师自身职业焦虑："AI/DevOps 时代测试岗会消失吗？往哪转？"

**语言信号**（中英双语）：
- 中文：测试团队转型 / QA 要不要独立 / 开发不写测试怎么办 / 测试的价值 / 测试部门拆分 / 角色认同 / 测试左移之后测试做什么
- English: test org transformation / should QA be independent / devs don't write tests / proving the value of testing / QA dissolving into dev / "I test, therefore I am" / future of testing roles / test designer vs test executor

**与相邻能力的区分**（初稿）：
- 与 `swe-set-te-role-model`（三角色模型）：那张卡回答"开发/测试开发/测试工程师各干什么"；本卡回答"这套角色分工本身会生什么病、往哪转"。前者是静态职责地图，本卡是动态病理诊断。二者构成"先懂角色、再懂角色缺陷"的顺序。
- 与 `crowd-and-dogfood-testing`（众包与内部试用）：本卡缺陷四给出"谁测不重要"的论断；那张卡给出落地组织法（任务包/导览/供应商）。本卡是"为什么"，那张卡是"怎么做"。
- 与 `test-certified-ladder`（测试认证分级）：认证分级是缺陷一的预防针（用阶梯把测试责任交还开发），本卡的转型机制一则是症状已重时的根治术。

## E（可执行步骤）

1. **采集组织现状**（输入=组织现状描述）：列出①角色结构（是否有独立 QA 部门、汇报线）；②开发是否写测试（提交前是否跑测试）；③考核指标（是否数 bug 数/用例数）；④典型事件（最近三次线上问题由谁先发现、谁背责）；⑤产物现状（用例库是否只增不减、测试计划是否有人看）。完成标准：五项各有事实性描述，无臆断。
2. **症状→缺陷映射**：把每个症状映射到四缺陷编号（允许一个症状命中多个缺陷），标注证据强度。完成标准：每个症状有缺陷编号；证据不足的如实标"证据不足"，不硬贴标签。
3. **开转型处方**：对命中的缺陷给出对应动作——缺陷一→把可测试性等测试特性列为产品特性、由新成员负责作热身项目；缺陷二→以产品为组织与认同单位（"我在为 X 工作"）；缺陷三→考核改看"对代码的影响"、删除无用产物、计划改用 ACC；缺陷四→TE 收缩为测试设计师，经营 dogfood/众包/早期用户。完成标准：每个命中缺陷至少一条可执行动作，且指明责任层级（个人/经理/总监）。

**输入契约**：组织现状描述——角色结构、开发测试比、考核方式、典型质量事件（最好含具体事例，而非只有口号）。
**输出契约**：症状→缺陷映射表 + 转型处方清单（每条含第一步人事动作与责任层级）。
**判停点**：①症状信息不足以判断某缺陷时，停止映射并补采集，不得凭印象诊断；②组织尚无基本开发测试协作历史（无 CI、开发零测试）时，先做基础建设（参考 `test-certified-ladder`），直接套用转型机制会失败；③处方涉及裁撤/合并部门时，向决策者如实转达书中原话"我们唯一可以做的就是推测"——这是推测而非定论。

## B（边界）

**反场景**：本卡不适用于尚未建立任何专职测试的组织（无病可诊）；不适用于强监管行业（航空/医疗）中外包测试与独立验证是合规要求而非缺陷的场景；"开发全责质量"在安全关键软件上不能照搬——独立验证与确认（V&V）在这些领域有其正当性。
**书中失败模式**：作者诊断的四缺陷全部来自 Google 自身（1200 人规模的工程生产力部门），且作者明言这是推测（5.1 末："我们正进入一个未知的领域"）；第1章 ce07 同时警告"测试为开发让路"的传统组织（测试无独立否决权、反复以补丁包收尾）也是失败模式——注意这与"拆掉独立测试"方向相反：两种病都存在，去中心化的前提是开发真正承接质量责任，否则只是把质量责任扔进真空。
**作者盲点/局限**：①2012 年语境——成书时"测试的去中心化已经在 Google 发生"（工程生产力部门拆分融入产品团队）；此后行业 DevOps、"你构建它你运维它"、测试左移的走向与书中预言方向大体一致（如实说明：预言已部分成真），但"TE 转型为少数高薪测试设计师"在多数公司远未实现，Google 自身也经历了反复。②转型方向非唯一解——作者给出的两个机制（测试特性一等公民、TE 转设计师）是 Google 语境（高技术水位、稀缺招聘）下的推演；技能不足的开发团队照搬会把测试责任推给最没有能力承担的人。③本书自身也有时间戳：作者在 5.6 批评"死守数十年之久的测试教条无异于刻舟求剑"——本书教条同样适用此警告，使用时应取诊断结构（症状→病理→处方）而不要照抄 2012 年的处方剂量。
