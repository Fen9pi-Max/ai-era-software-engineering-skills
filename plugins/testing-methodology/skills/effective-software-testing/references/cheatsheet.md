# 决策规则速查 — 有效软件测试——提高测试的 50 条建议（Effective Software Testing: 50 Specific Ways）

| 能力 | 一句话规则 |
|---|---|
| 需求可测试性审查与优先级 | 用十属性清单+质量测度标准+奖励惩罚打分审查需求可测试性并排优先级 |
| 测试工作量估计四法 | 用开发比例/人员比例/测试过程/任务规划四法估测试投入并互相印证 |
| 测试数据设计（深度·宽度·范围·完整性·条件） | 按深度/宽度/范围/完整性/条件五维度设计测试数据并外置为数据表 |
| 测试设计技术组合（五法+辐射分析+探索性） | 组合功能分析/等价类/边界值/路径/正交排列设计用例，辐射分析覆盖变更影响 |
| 实用单元测试（分层·先写·接入生成） | 分层不隔离的实用单元测试，实现前开发并接入每日生成 |
| 自动化期望纠偏与工具选择 | 用十项纠偏对齐期望，九步框架选工具，原型验证与自制成本权衡 |
| 自动化脚本工程五技术 | 数据驱动/模块化/对象名导航/函数库/版本控制重构脆弱脚本，适配器绕过 UI |
| 回归·烟雾·自动生成流水线 | 编译→烟雾→回归的阻断式流水线，冲击矩阵覆盖数据依赖方 |
| 非功能测试框架（性能·并发·安全·兼容） | 性能梯度找上限、并发按模型定测试点、安全双层验证、兼容按频率排序 |
| 缺陷生命周期与测试执行度量 | 一报告一缺陷的状态机流程 + 步骤级执行%、持续时间、趋势、重现率、密度六度量 |

> 速查只给结论；需要原文依据、案例或反例时读对应能力卡。
