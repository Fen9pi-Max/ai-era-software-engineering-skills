# 测试设计技术组合（五法 + 辐射分析 + 探索性）

## R（原文摘引）
> 综合使用多种测试技术比使用单一的测试技术更有效。（第5章 第25条）

> 只验证这种变化本身还不够……有效测试还必须要覆盖到这种变化所影响的其他所有部分。（第5章 第22条）

## I（解释）
五种技术及选用：
1. **功能分析法**：每个功能至少一个测试过程，"证明系统提供了功能 x"。
2. **等价类划分**：产生相同结果的输入归一类，每类只测一个代表（密码 10/11/12 位同属非法类）。
3. **边界值分析 + 负面测试**：边界把数据分三组（内/上/外）；取最大/最小、刚大于/小于、0、null；追问"只接受数字的域是否接受字母？保留字符是否引起崩溃？"。
4. **路径分析法**：白箱级（代码路径，单元测试）或黑箱级（功能层路径）。
5. **正交排列**：3 参数×3 取值全组合 27 例 → 正交表 9 例；依据是多数错误只依赖成对参数（强度 2）。
**辐射分析**（需求→用例）：验证 UI 行为 → 正负数据组合 → SQL 验证落库 → 追问"变化还影响哪些部分"并验证所有依赖功能（编辑客户名 → 订单模块用新名称、旧功能无副作用）→ 直到所有受影响部分覆盖。
**自动化候选 8 判据**：需多次执行、高风险、有规律运行（烟雾/回归）、手动不可能（千用户并发）、多数值同动作（数据驱动）、多配置基线、结果可预测、系统基本稳定；反之手动。
**探索性测试**：适用无文档/定阈值场景；不可预先规划，但执行前后必须文档化并纳入回归；只能作为功能分析的增强。

## A1（原书案例）
- 编辑客户名称需求的辐射分析全过程（第22条）。
- 正交排列 27→9 算例（第25条）。
- 选择列表项上限：逐步加项找出性能阈值→客户认可→公布（第27条）。

## A2（情境应用）
拿到功能需求后：①功能分析列功能清单；②对输入密集功能用等价类+边界值生成场景；③对参数组合爆炸用正交排列（强度2）压缩；④对每个状态变更做辐射分析找受影响功能；⑤按 8 判据标注哪些场景值得自动化。

## E（评测）
- 输入：一段真实功能需求。
- 输出：测试用例集（含技术标注）+ 组合压缩说明 + 影响分析清单。
- 通过标准：等价类无冗余代表；边界三类齐全；组合数较全组合显著缩减且成对覆盖；变更影响功能均有用例。

## B（边界）
不生成代码级白箱路径（属单元测试能力）；覆盖率度量不在本能力内；需求本身不可测试时先走需求审查能力。
