# 测试工作量估计四法

## R（原文摘引）
> 因为估计公式往往不够准确，使用复杂的方程一般也没有什么用处……简单的估计模型反而比较有效。（第2章 第12条）

## I（解释）
四个互补方法，按组织数据成熟度选用：
1. **开发比例法**：测试人数=开发人数/比值。口径：大市场商业产品 3:2、小市场商业 3:1、单客户+COTS 集成 4:1、政府内部 5:1、企业内部 4:1。
2. **项目人员比例法**：测试组占项目总人数比例——大市场商业 27%、小市场 16%、单客户 10%、单客户+COTS 14%、政府 11%、企业 14%。
3. **测试过程法**：历史因子（人·小时/测试过程，如 6.16）× 新项目预计测试过程数 ÷ 时间跨度（人年 2080h）= 全职测试工程师数。例：1120×6.16÷(12×173)≈3.3 人。
4. **任务规划法**：按测试阶段历史人·小时百分比分解（测试开发 37%、测试执行 17%、测试计划 10%、测试设计 10%、管理支持 9%……），删去不适用项后除以时间跨度。
调整因子：组织成熟度、工程师技能、工具熟练度、商业知识、测试启动早晚、计划版本数、高风险应用、时间充足度。

## A1（原书案例）
第12条完整算例：30 名开发按 3:2~5:1 → 测试组规模；测试过程法 1120 个过程 ×6.16=6900 人·小时 ÷12 个月 → 3.3 人；任务规划法 6403h ÷2080h ≈3.1 人——三法互相印证。

## A2（情境应用）
估新项目测试投入时：①先判断项目类型选比例口径得出粗估；②若有历史数据，用测试过程法/任务规划法细化；③无历史数据时明示"比例法仅数量级估计"；④列出适用的调整因子并说明增减理由；⑤输出人·小时、人数、时间跨度三口径。

## E（评测）
- 输入：项目类型、开发人数/总人数、（可选）历史测试过程数据。
- 输出：至少两种方法的结果对照 + 调整说明。
- 通过标准：两法结果同数量级；算术可复算；调整因子有明确理由。

## B（边界）
历史数据须来自测试文化成熟后的项目，否则因子失真；不覆盖测试环境采购成本（另见环境规划）；不替代与开发/管理的协商。
