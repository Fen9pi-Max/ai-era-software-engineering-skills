# 测试数据设计（深度·宽度·范围·完整性·条件）

## R（原文摘引）
> 错误集中在边界上发生，因此，在边界上测试系统的行为是一种非常有效的测试技术。（第2章 第10条）

## I（解释）
**四维度评审 + 条件预置**：
1. **深度**（记录数量/规模）：功能测试早期用小库；性能/容量测试必须用生产规模数据——在 100 条记录库上做性能测试毫无意义。
2. **宽度**（数值与类型变化）：如负余额、100/1,000/100,000/10,000,000；存款/支票/贷款等类型变化。
3. **范围**（精确度、相关程度、完整度）。
4. **执行期完整性**：测试数据隔离（独立数据库或功能领域不交叉）、可恢复初始状态、防并发干扰。
5. **条件**：直接构造目标状态数据（如"年终出清"状态），免去输入全年数据的漫长过程。
**边界值集**：100+1(外)/100-1(内)/100(上)/1(上)/null/0；需求未指定边界时用原型+探索确定。
**数据外置**：测试过程不内嵌具体数据；数据场景放数据表（每行=一个用例，含实际结果列），过程引用之；数据限制查数据字典。

## A1（原书案例）
- 银行账目系统：负余额、多档金额、多账户类型设计宽度。
- 登录验证数据表：位数多一/少一/相同、允许/不允许字符、零输入、空输入 × 拒绝/接受。
- 财务系统"年终出清"状态数据直接预置。

## A2（情境应用）
为任一被测功能设计数据集时：①查数据字典找边界与类型；②按边界值集生成基础场景表；③按四维度评审补缺口（尤其性能数据规模）；④把场景做成外部数据表并设计恢复初始态机制；⑤需要长流程才能到达的状态用条件预置。

## E（评测）
- 输入：字段定义/数据字典 + 测试类型（功能/性能）。
- 输出：数据场景表（含边界与非法值）+ 规模与隔离方案。
- 通过标准：每个数值字段至少覆盖边界内/上/外与空/0；性能场景数据规模匹配生产。

## B（边界）
随机生成数据只适性能测试，不适功能测试（不反映真实场景）；数据管理工具选型不在本能力内。
