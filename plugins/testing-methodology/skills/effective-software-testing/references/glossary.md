# 《有效软件测试》术语表（精选）

- 可测试的（testable）：能为需求设计出可执行、输出可预知且可验证的测试过程
- 质量测度标准（quality measure）：区分满足/不满足需求的判定尺度
- CCB（变更控制委员会）：评审、批准并传达变更请求的跨部门机制
- 黑箱/灰箱/白箱测试：仅经 UI 验证 / 兼监视内部组件行为 / 针对源代码路径
- 烟雾测试（smoke test）：回归套件的精简版，版本进入测试的入口标准
- 回归冲击矩阵：记录代码变化可能影响的所有区域（含数据依赖方）的矩阵
- 测试外壳/测试包（test shell/wrapper）：按预定顺序回放一组测试过程的组织形式
- 自制测试工具（test harness）：绕过 UI 直接测后端核心逻辑的自研工具
- 适配器（test-harness adapter）：封装系统差异、使同一套用例可多系统执行并比较
- 数据驱动（data driven）：数值从外部数据源读取而非硬编码
- 存根（stub）：返回预定义结果的临时替身，支持测试先行
- 单元测试框架：统一加载测试列表、处理命令行与错误、报告整体结果的机制
- 自动生成（automated build）：定期用最新稳定代码自动完成的系统构建
- 边界内/上/外（in-/on-/out-of-bounds）：边界把数据分成的三类
- 正交排列：用最小用例集实现参数两两组合最大覆盖（强度 2）
- 前提功能（precursor function）：其他功能的基础与前提、须优先测试的功能
- 保守/开放/无保护并发：加锁拒绝他人 / 保存时检测冲突 / 最后保存者获胜
- 缺陷持续时间（defect aging）：发现→改正的时间跨度
- 重现率/修改质量：修正后在原正常功能上新引入或重现缺陷的比率
- 缺陷密度：某需求发现的缺陷总数 ÷ 为该需求执行的测试过程数
- 入口/出口标准（entrance/exit criteria）：测试周期开始/结束的条件
- 可测试性钩（testability hook）：专为测试插入程序的代码
