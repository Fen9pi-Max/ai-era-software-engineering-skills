# 猴子测试与可靠性度量

## R（原文摘引）
> 测试猴子是补充，而不是替代现有的自动化测试和手动的测试。（第24章）

> 可靠性 = Σ随机操作数 /（Σ失效数 + 1）。（第24章 度量公式概括）

## I（解释）
猴子测试五大特性：①随机从操作列表选命令，经真实用户接口输入；②监测"生命体征"（是否失去响应）；③健壮日志（蓝屏后仍保留、可回放、崩溃时截图+资源使用）；④崩溃后自动重启并初始化 SUT；⑤继续测试。
导向技巧：提高特定命令频次、删除离开目标区域的命令、顺序测试带到目标区域再放开随机。
度量：可靠性（MTBF 等价）按 build 画趋势线，设系统测试准入下限与发布上限；有效性 = 新缺陷/小时×24，随构建数趋于 0。
用法：每日构建冒烟验证、准入门槛、无人值守（夜间/周末/多机并行）。

## A1（原书案例）
第24章丹麦医疗设备：FSM 为 SUT 建模+oracle 软件，发布前发现大量其他方法难找的 bug；第13章：可靠性测试首战即挡下一次问题发布（周期 15→5）。

## A2（情境应用）
对需要稳定性证明的系统：写操作列表脚本+崩溃检测+自动重启；每日构建跑 N 小时；按 build 记录 MTBF 画趋势，低于准入线阻塞进入系统测试。

## E（评测）
输入：某应用的功能列表与已知崩溃历史；输出：猴子工具规格（操作列表、生命体征判据、重启策略）+ MTBF 准入/发布阈值方案。通过标准：五特性齐备；阈值有历史数据或分位数依据。

## B（边界）
发现的多是崩溃/健壮性问题，不验证业务正确性；知识型猴子（FSM+oracle）成本接近 MBT；与 SUT 无需同步是其优点但意味着不能断言中间状态。
