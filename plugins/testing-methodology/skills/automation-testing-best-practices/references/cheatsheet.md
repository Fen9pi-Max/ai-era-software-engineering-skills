# 决策规则速查 — 自动化测试最佳实践（Experiences of Test Automation）

| 能力 | 一句话规则 |
|---|---|
| 测试件架构：抽象层次设计 | 用工具隔离层+领域测试层两层抽象设计可长期维护的测试件架构 |
| 是否自动化某测试的决策检查清单 | 用10条判据决定哪些测试值得自动化、哪些显式暂缓 |
| 自动化测试 ROI 评估 | 用多周期工作量模型、执行频率模型与缺陷成本公式算自动化收支平衡点 |
| 自动化试点项目方法论 | 用有目标、有时间盒、有量化基线的试点廉价验证自动化路线并赢得支持 |
| 测试结果验证与僵尸测试防御 | 期望结果负责制+静态分析+测试生命周期状态机，防住永远绿色的僵尸测试 |
| 失败分析与日志设计 | 失败瞬间自动留存上下文（日志+截图+环境+故障签名），把失败分析成本降到最低 |
| 基于模型的测试（MBT）工作流 | 状态机建模+组合数据+路径生成算法，让变更只改模型就重生成全部用例 |
| 猴子测试与可靠性度量 | 随机操作+生命体征监测+自动重启，按 build 画 MTBF 趋势线设准入与发布门槛 |
| 测试件标准、复用与文档 | 命名约定+脚本标准头+复用分级+测试选择器，让测试件可协作可检索 |
| 自动化测试反模式清单 | 按选型/启动/构建/运行/组织五阶段的24个失败模式对照体检并给对策 |

> 速查只给结论；需要原文依据、案例或反例时读对应能力卡。
