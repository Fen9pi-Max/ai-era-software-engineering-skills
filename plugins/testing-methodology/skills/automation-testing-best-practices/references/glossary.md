# 术语表（Glossary）

| 术语 | 定义 |
|---|---|
| testware（测试件） | 自动化测试所需的全部制品：脚本、数据、文档、环境信息、实用工具等，需要架构设计与维护。 |
| testware architecture（测试件架构） | 测试件的组织结构与依赖关系；正确的抽象层降低维护成本并提供灵活性。 |
| abstraction layer（抽象层） | 面向测试工程师、隐藏底层技术细节的接口；过厚或过薄都有代价（第18章）。 |
| DSTL（领域特定测试语言） | 面向特定领域的关键字/参数语言，让非编程测试人员编写自动化测试。 |
| object map（对象映射） | GUI 对象名字的集中映射表；对象改名只改映射不改脚本。 |
| wrapper（包装器） | 包裹 UI 对象或底层 API 的封装代码；必要但不充分。 |
| keyword-driven testing（关键字驱动） | 用关键字表达测试步骤，便于非技术用户创建用例。 |
| data-driven testing（数据驱动） | 同一脚本配多套数据集执行，适合多数据集回归。 |
| test harness（测试用具） | 执行用例并判定成败的支撑代码与环境。 |
| test oracle（测试预言） | 判定结果是否正确的机制；可只实现部分 oracle（如仅查存活）。 |
| model-based testing, MBT（基于模型的测试） | 用模型（常为 FSM）描述 SUT 并自动生成/执行用例。 |
| monkey testing（猴子测试） | 随机测试执行工具：随机选输入并检查崩溃，评估稳定性与可靠性。 |
| disposable script（一次性脚本） | 单一目的快速编写、用完即弃的脚本，也有短期价值。 |
| zombie test（僵尸测试） | 存在却不再执行有效检查的无用脚本，永远显示绿色。 |
| pilot project（试点项目） | 小范围验证工具与方法再推广的做法。 |
| SUT（待测系统） | 被测软件系统；自动化方案不应侵入 SUT。 |
| test architect / test automator | 架构师设计测试件整体结构；自动化人员实现脚本/数据/工具与多层抽象。 |
| TiP（Testing in Production） | 自动化测试扩展到生产环境持续运行。 |
| regression suite（回归套件） | 检测变更引入回归的测试集合；应精化控制时长与维护成本。 |
| smoke test（冒烟测试） | 覆盖核心路径的轻量测试。 |
| test automation pyramid（自动化测试金字塔） | 单元测试多、业务逻辑居中、GUI 测试最少的分层模型。 |
| automation test lifecycle（测试生命周期） | 开发→评审→候选→有效→挂起→退出的状态流转管理。 |
| MATS（最小验收测试套件） | 代码检入前必须通过的最小测试集（第2章）。 |
| capture/replay（捕获/回放） | 录制手动操作再回放；同步困难、难复用。 |
| test selector（测试选择器） | 按标签选择执行子集的机制（第11/25章）。 |
| script creep（脚本蔓延） | 脚本无节制增长、顺手加额外验证导致定位噩梦（第27章）。 |
| quick win（快速回报） | 早期即能展示价值的外围自动化（安装、数据分发等）。 |
| probe effect（探测效应） | 测试手段自身改变系统行为；非侵入设计可避免。 |
| BHAG（胆大包天的目标） | 用于换取组织支持的宏伟目标（第27章）。 |
| EF/DET | SAP 最小可复用构建块（基本功能/日终处理）模块化方式（第15章）。 |
