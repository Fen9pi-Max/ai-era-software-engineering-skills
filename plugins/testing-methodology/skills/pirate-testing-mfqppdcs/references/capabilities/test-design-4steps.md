# 测试设计四步法：从 TCon 到测试实例（Te）

## R（原文摘引）
> 识别测试条件中可变化的部分（变量）→ 为每个变量确定具体取值 → 得出测试实例。

> （选取数据）禁用"有效的""正常的"这类模糊字眼。

## I（解释）
1. **识别变量**：找 TCon 中取值可变化的部分；诀窍——"假想立即要执行测试，需要设置哪些参数、准备哪些数据？取值未定者即变量"；固定的（如数量=1、无优惠）不算。
2. **变化数据**：对每个变量做等价类+边界值分析；正常场景只分析有效等价类+有效边界值，异常场景只分析无效等价类+无效边界值。
3. **选取数据**：具体明确（禁模糊字眼）+ **多样化原则**：单价选 {0.00}免费/{0.01}最小非免费/{99.99}全9/{345.60}尾数为0/{65535.99}最大；编号补 135789、666666 使 0-9 每个数字都被覆盖；名称覆盖 1~5 字及"天天天"3字相同。
4. **得出测试实例**：组合成实例表，编号 Te-TCon001-001…（关联 TCon 编号）。
执行中想到此前分析未覆盖的必测场景，直接补入表格——"不要拘泥于外在的形式，毕竟找到 bug 才是我们真正的目的"。

## A1（原书案例）
TCon-001"购买 1 件普通无优惠商品"：变量=商品编号/名称/单价（数量、类型、优惠固定不算）；编号 00000~99999 及边界；单价多样化五值；产出 Te-TCon001-001~005。
my chat 登录：昵称限 1-6 位小写字母数字首字符字母，同一 TCon 下小 A 测"a""b"通过、小 B 测"a""z"失败——缺陷常只与具体取值相关，这是显式做 TD 的理由。

## A2（情境应用）
拿到 TCon 清单后：
1. 逐 TCon 列变量（假想法）；
2. 每变量做等价类/边界值表（正常/异常分开）；
3. 按多样化原则挑具体值；
4. 输出 Te 编号表，可直接交付执行或转自动化脚本参数。

## E（评测）
- 输入：2 个 TCon（一个正常一个异常，含 3 个隐含变量）。
- 输出：变量表+取值表+Te 实例表。
- 通过标准：识别出全部 3 个变量；无模糊取值字眼；取值覆盖边界且体现多样化（含免费/最小/全9/最大类值）。
