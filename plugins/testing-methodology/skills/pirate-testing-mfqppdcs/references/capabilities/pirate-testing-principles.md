# 海盗派测试原则与观念（Tests ≠ Testing）

## R（原文摘引）
> Tests 是设计出来写成文字的东西，代表我们对被测对象的认知和猜测；Testing 需要与真实被测对象接触，去挖掘未知的需求、未知的风险、未知的 bug 和未知的行为。

> Apply Heuristics, Not to Follow Them（应用启发式，而非照搬）。

## I（解释）
16 条核心观念（分组）：
**世界观**：质量是主观的（Quality Is Value To Some Person）；bug=威胁产品价值的任何东西；测试人员像科学家，处于反馈环核心。
**方法论**：TESTS ≠ TESTING；从实际问题出发而不是从方法出发；设计更多 test ideas ≠ 更好分析；风险不断变化→分析注定迭代；Heuristics 应用而非盲从，警惕柏拉图化（重形式轻内容）；步骤不是标准流程，测试基于上下文。
**协作**：分析与执行不可分（反对岗位割裂）；最好的测试人员是让合适的 bug 得以修复的人（Kaner）；每个问题几乎都对应某个风险。
**宣言**：不循规蹈矩但 Know Your Mission；基于风险不断调整而非照计划行事；关注思维和技能；敬仰测试匠艺；对未知充满好奇。

## A1（原书案例）
KYM 反模式三条（形式化/重结果/陷细节）；"别把步骤当作标准的测试分析过程——测试要基于上下文"；TD 是否显式做由上下文定（外包、审计场景必要）。

## A2（情境应用）
评审测试方案/团队流程时逐条对照：是否重形式轻内容？是否一次性分析不迭代？是否把 Tests 当 Testing？分析执行是否割裂？输出偏差与修正建议。

## E（评测）
输入：一段体现"重形式、一次性分析、Tests=Testing"误区的工作方式描述；输出：命中观念+修正建议。通过标准：识别全部三类误区并引用对应原则。

## B（边界）
观念层能力，具体操作见各专项卡（KYM/TCO/Modeling/TD/TE）。
