# TCO：测试覆盖大纲

## R（原文摘引）
> 内容重组包含两层意思：对信息源中提取的信息进行重新组织，以及对于信息源中没有的信息的添加。

## I（解释）
TCO = 从测试角度定义需求的信息重组产物，达成三个效果：**信息提炼**（Curation，过滤掉无需关注的）、**内容重组**（重新组织+补充新信息）、**心中有数**。
画法（0.5~2 小时）：
1. 边读文档/听交流边记录，KYM 已知的概况不再记；
2. 遇疑问即记；需求变动处必记（凡变动处都可能有风险）；
3. 可选 10 分钟限时头脑风暴，笔不停列所有测试点；
4. 重组为思维导图，分支归类规则：
   - 独立功能点 → M 分支
   - 两个及以上部分的交互（时间/空间）→ F 分支
   - 非功能质量属性（性能、兼容…）→ Q 分支
   - bugs / Risks / Questions 各设分支（或在 M/F/Q 旁加"？"）
一级节点二选一：MFQ 思路（深入系统分析）或 SFDIPOT（快速出 test ideas）。
无文档时三途径：读文档 / 找人交流头脑风暴 / 直接探索程序边测边画。

## A1（原书案例）
"番茄快点"App：15 分钟探索性测试边测边画 TCO。大富翁练习：10 分钟头脑风暴罗列测试点再按 M/F/Q/Questions/Risks 归类；发现 KYM 需更新则及时更新——TCO/KYM 都不是一次性工作。

## A2（情境应用）
拿到需求文档/用户故事/PRD 要快速确定测试范围时：
1. 通读一遍，第二遍按分支规则边读边记；
2. 输出 TCO 导图（M/F/Q + Questions/Risks/Data 分支）；
3. Questions 分支每条指定追问人；Risks 分支标 L×I；
4. 用 TCO 和干系人评审测试范围，防遗漏。

## E（评测）
- 输入：一份混合了功能点、交互场景、性能要求、含糊描述的模拟需求（植入 2 处交互、2 处非功能、3 处模糊点）。
- 输出：TCO 导图。
- 通过标准：交互类进 F、非功能进 Q、模糊点进 Questions，无漏分类；M 分支粒度为可独立测试的单功能。

## B（边界）
F/Q 不求完整，目的是防遗漏；单功能划分无唯一答案，粒度不当可后拆合；深入建模见 modeling-workflow。
