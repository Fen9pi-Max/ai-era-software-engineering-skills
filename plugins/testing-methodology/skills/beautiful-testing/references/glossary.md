# 术语表（Glossary）

| 术语 | 定义 |
|---|---|
| 测试利益相关者/反利益相关者 | 所有与测试及质量相关的角色；反利益相关者希望项目失败（如被替代系统的维护者），须识别应对。 |
| 有效-高效-优雅 | 测试三维评价：满足干系人目标 / 资源价值最大化 / 重压之下不失风度。 |
| 外在美/内在美 | 外在=面向干系人成果的度量（DDP/ROI）；内在=测试内部流程度量（RTA/RRC/ART）。 |
| DDP | 缺陷发现百分比=测试发现/(测试+产品发现)×100%；独立系统测试约85%基准。 |
| Test ROI | (节省的外部故障成本−测试投资)/测试投资；实测 25%~3500%。 |
| RTA/RRC/ART | 回归自动化百分比 / 回归风险覆盖率 / 回归加速比（内在美三指标）。 |
| GQM | 目标-问题-指标法：从干系人期望出发构建度量。 |
| TCE | 测试用例有效性=(Nt/Ntot)×100%，可按 P1=10…P5=1 加权。 |
| 测试逃逸 | 正常 QA 周期之外发现的缺陷；六类原因逐类纠正。 |
| 元缺陷（meta-bug） | 只含最小键值指向上游缺陷库的轻量本地跟踪层。 |
| 优先级 vs 严重度 | 优先级=按政策多重要；严重度=影响多大；二者分离记录。 |
| 性能测试检查点 | 替代"性能测试用例"的条目，按用户负荷分级、直接映射报告项。 |
| 系统使用模型 | 客户+开发+测试白板共建的高峰期最流行+高风险功能区模型。 |
| 模糊测试（Fuzzing） | 随机修改/生成输入找崩溃类缺陷；常规（zzuf）/自定义/随机三级。 |
| 问题文件回归库 | 收集所有曾致崩溃的文件，防旧缺陷重引入并作模糊种子。 |
| 协议测试四层抽象 | 原始XML比对(反模式)→DOM断言→载荷抽象→序列化独立测试。 |
| 场景测试 | 用帮助方法序列描述复杂会话/状态机协议的高层测试。 |
| 无头交互程序 | 不经 UI 的小程序，一次性验证连接/认证/加密全链路。 |
| 失败分析 | 自动归因失败：区分产品bug与测试代码错误，同因多配置失败去重。 |
| 测试分配 | 测试控制器把用例与机器配置匹配执行的调度机制。 |
| refleak 检测 | 调试版连跑测试 2-3 遍比较引用总数，等量上升即泄漏。 |
| Buildbot | Python 持续构建系统：多架构每次提交自动跑测试。 |
| RNG 逐级测试 | 值域→均值→方差→卡方水桶→K-S，由简到繁的统计验证。 |
| 以变化为中心的测试 | 用调用图+测试映射只跑受影响测试；三度分离以外基本安全。 |
| 源/同步/管道函数 | 按调用关系分类：被多人调用 / 只调用别人 / 双向传播。 |
| SLIME | Security→Languages→requIrements→Measurement→Existing 高效测试顺序。 |
| 图案化文字（pseudolocalization） | 大写+首^尾$ 变换资源文件验证国际化完备性。 |
| Oracle 脚本 | 自动查库校验生成数据正确性的测试准则脚本。 |
| 变异测试 | 植入人为缺陷评估测试集检出能力；算子：改常量/取反条件/改操作符/省略调用。 |
| 等价变异 | 无实际影响的变异，用影响排序法过滤（<3%）。 |
| 参照测试（reftest） | 两段代码渲染逐像素比较的可视化回归测试；==/!=/fails-if。 |
| 检验 vs 调查 | checking=可自动化的重复确认；investigating=反馈驱动的人的智慧。 |
| 营养均衡早餐策略 | Socialtext 均衡测试组合：多手段覆盖多种失败方式。 |
| 黑天鹅回归取舍 | 一个反例比百万正例更有说服力；先问哪些测试一直没问题。 |
| 关键事件分析 | 讲述亲历关键事件提炼原则（源自 Kaner）。 |
| 实例（可执行规格） | 前置条件+行为=后置条件的持久需求工件；被执行时转为测试。 |
| 红-绿-重构 | TDD 循环：测试失败→实现通过→稳定点重构。 |
| 钢化线程（thin thread） | 端到端最基本功能切片先行，每线程可测可交付。 |
| ANSTE | XML profile 描述多机场景、虚拟机自动部署的网络服务测试套件。 |
| Spider/Sisyphus | 爬虫管理 URL / 启动浏览器收集泄漏崩溃的百万网页测试组合。 |
| Lithium | 自动缩减失败页面为最小用例（3000行→5-10行）。 |
