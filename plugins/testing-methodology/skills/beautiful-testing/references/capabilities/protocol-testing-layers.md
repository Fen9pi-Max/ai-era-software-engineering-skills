# 协议测试四层抽象与场景测试

## R（原文摘引）
> 我们的测试实际上同时测了两个东西：协议的逻辑（响应的内容）和响应的表示……为了在我们的测试中把逻辑从表示中分离开来。（第7章）

## I（解释）
**四层抽象**（防脆弱）：
- L1 原始序列化 XML 比对（**反模式**：属性顺序/空格等表示变化即全挂）；
- L2 结构化 DOM 断言（逐属性，不受序列化影响但冗长）；
- L3 高级载荷抽象：工作于 `IQ + VersionPayload` 等数据结构，只断言业务字段；**逻辑与表示分离**；公共部分抽到通用基类单独测；
- L4 载荷序列化独立成测试类。
接口设计：依赖抽象 DataChannel/XMLElementChannel，Mock 可注入。
**多级协议**：响应映射表 `itemsResponses[JID]=...` + 自动应答器回调（收到 Get 型 IQ 查表回注响应；未知 IQ 则 FAIL）；每级响应（成功与错误）各建精简测试。
**场景测试**（复杂状态机协议）：帮助方法序列描述会话（sessionOpensConnection(); serverAcceptsConnection(); ... ASSERT(...)）；边缘案例（强制加密服务器不支持→serverSendsStreamFeaturesWithoutStartTLS(); ASSERT(hasError())）；规则：各级边缘单测，**级间交互必用场景**。
**无头交互程序**：不经 UI 的小程序（连接→认证→发请求→无错退出码 0）一次验证全链路；环境变量传多服务器凭据；**缺陷回流**：因实现缺陷失败→加单元测试并修复；因组合问题→加场景测试。

## A1（原书案例）
XMPP Swift 客户端（C++）：disco 多级链式协议、会话初始化（TLS 协商）、对多种真实服务器跑 ClientTest。

## A2（情境应用）
测试网络协议/API 客户端时：按四层设计断言层级（禁止 L1 字符串比对）；多轮请求用响应表+自动应答；握手/状态流用场景帮助方法；上线前跑无头全链路程序。

## E（评测）
输入：一个两步请求-响应协议描述；输出：分层测试方案（L3 断言+响应表+至少一个边缘场景）。通过标准：无原始字符串比对；响应表覆盖成功与错误。

## B（边界）
服务端/单测工程细节随栈而异；UI 层测试另见大规模自动化运营卡。
