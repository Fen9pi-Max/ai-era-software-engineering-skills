# 模糊测试三级策略

## R（原文摘引）
> 从你的缺陷跟踪库里找样本。这些文档……很可能过去曾引起过问题。（第5章）

> 当你的模糊测试不再发现缺陷时，那正是你应开始采用你的模糊器的更高级功能之时。（第5章）

## I（解释）
1. **样本准备**：缺陷库附件首选（回链"缺陷123附件456的模糊版"）；补充相似产品缺陷库、按扩展名搜索、自造覆盖新功能。
2. **三级策略**（按收益递减晋级）：
   - 常规模糊：zzuf 默认翻转 0.4% 比特（`zzuf <原文件 >模糊文件` + `程序 模糊文件`，脚本化监视退出码/错误消息；可保护字节范围如文件头）；不再发现缺陷→启用高级功能（xor→set/reset）→普遍缺陷修复后**降低比例**找局部功能缺陷
   - 自定义模糊：针对格式/功能写专用生成器（先找现成如 jsfunfuzz）；示例：函数名+操作符+随机参数生成万级公式，`={}` 三字符即崩溃
   - 随机模糊：无结构输入（超长随机行）消除样本与自定义器的偏见
3. **容器格式**（zip+xml 如 .xlsx）：先解压再模糊，保护标记与 XML 非法字符。
4. **配套**：模糊文件写单元测试防回归；代码覆盖工具找盲区（模糊器有偏见，如总正确闭合括号就发现不了失配）。
5. **ClamAV 加成**：问题文件回归库（曾致崩溃的文件留存，防旧缺陷重引入+作种子）；数量多多益善；监视用户缺陷报告反哺模糊器（陌生函数加入）。
6. **局限**：擅崩溃/挂起/泄漏，不擅正确性判断；稳定信号=发现缺陷成为例外→转回归工具。

## A1（原书案例）
Gnumeric 用 zzuf+自定义公式模糊器发现数十个崩溃缺陷；Python 用 Fusil 发现 `audioop.findmax()` 负参崩溃；ClamAV 在 Valgrind 下扫海量模糊文件找极少路径的泄漏。

## A2（情境应用）
对有文件/协议/输入解析的程序：
1. 从缺陷库收集种子文件 20-50 个；
2. zzuf 批量模糊跑一晚，收集崩溃/挂起（退出码+日志）；
3. 每个崩溃最小化并写回归测试入库；
4. 收益递减后针对核心格式写自定义生成器；
5. 建问题文件库持续积累。

## E（评测）
- 输入：目标程序输入格式说明+现有缺陷附件若干。
- 输出：模糊测试方案（工具链/种子来源/晋级触发条件/回归库设计）。
- 通过标准：三级策略与晋级信号齐备；含容器格式处理与覆盖盲区应对；崩溃处置含最小化+回归测试。

## B（边界）
不验证业务正确性（配 oracle 脚本，见 slime-efficient-testing）；不替代安全审查；GUI 程序需额外驱动层。
