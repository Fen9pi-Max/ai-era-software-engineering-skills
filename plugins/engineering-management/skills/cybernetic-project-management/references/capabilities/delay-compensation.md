# 时滞补偿（历史区间思维 + 最坏情况无条件稳定）

## R（原文摘引）
> 压力变化的趋势(方程左端)不仅依赖于当时的压力 φ(t)，而且明显地依赖于过去的历史状况 φ(t−τ) 和 μ(t−τ)，τ>0。……为了求解方程式初值不能只给在初始瞬时 t=t₀，而必须给在一个区间上。（第十一章 11.2）
> 我们来处理最坏的可能性 n≃1，并且在这种情形下进行设计，使系统是无条件稳定的。这样设计出来的系统对于所有可能的 n 的值，当然都是稳定的。（第十一章 11.7）

## I（解释）
1. **当前状态由历史区间决定**：有反馈延迟的项目里，今天的局面是过去一个延迟周期内所有动作的合力，不是昨天单日的结果。分析问题必须回看长度 = τ 的窗口，只看当前快照必然误判。
2. **在途动作未兑现**： τ 时刻前发出的纠偏动作此刻尚未生效。不盘点在途动作就追加新动作 = 对同一偏差重复用药，这是振荡的主因。
3. **延迟侵蚀稳定域**：反馈越慢，能容忍的控制力度越小——"催得越勤、管得越狠"在延迟系统里反而发散（越纠越振荡）。
4. **最坏情况设计**：延迟准确值通常未知。对策：按物理上可能的最坏延迟设计控制规则仍须收敛（无条件稳定），则对一切实际延迟都稳；参数不确定时取保守边界做计划，按最坏成立的方案自动覆盖全部情形。

## A1（原书案例 + 合成演练）
- 原书：导管压力系统方程含 φ(t−τ)、μ(t−τ) 项，初值必须给在一个区间上而非一个瞬时（11.2）；反馈伺服机构随时滞增大稳定域缩小，工程上按最坏 n 值设计无条件稳定（11.7）。
- 合成演练（原书未提供项目案例）：状态报告延迟 2 周 → 周一看到"进度落后 1 周"，但两周前已批准的支援措施此刻刚生效 → 误判处理：立即再抽 3 人救火 → 三周后人力过量、返工涌现，进度反向震荡。正确处理：盘点在途措施（占偏差 0.8 周）后净偏差仅 0.2 周，不追加动作，下期复评。

## A2（情境应用）
场景：汇报链/审批流长导致决策滞后时；纠偏动作发了没反应、忍不住再加码时；外包/异地团队反馈周期长时；"为什么越管越乱"的困惑时。
语言信号：「措施还没见效要不要再加码」「汇报太慢了」「为什么越催越乱」「审批要等两周」「lag / latency / 越纠越乱」。
区分：noise-filtering-estimation 区分噪声与趋势（测量质量）；本卡处理动作到见效的因果延迟（结构问题）；feedback-cadence-design 定节拍，本卡为节拍补提前量。

## E（执行步骤）
输入契约：主要反馈回路的延迟估计（或其范围）+ 最近 2τ 窗口内已发出的纠偏动作清单 + 当前偏差。
1. 估计各环节延迟 τ（报告链、审批、招聘、学习曲线），列出最大 τ。完成标准：τ 表（值或区间）。
2. 历史区间复盘：用长度 2τ 的窗口（而非单点）解释当前状态——窗口内哪些动作已生效、哪些在途。完成标准：在途动作清单及预期兑现量。
3. 净偏差 = 表观偏差 − 在途动作预期效果。净偏差小 → 不动；净偏差大 → 进入第 4 步。
4. 按最坏 τ 设计纠偏力度：假设新动作也要 τ 才见效，选"即使延迟这么久也不会过冲"的最小充分动作；并发送可提前的短延迟信号（预警、预授权）压缩 τ。
5. 下一个 τ 内冻结同类动作，到期复评，防止重复用药。
输出契约：τ 表 + 在途盘点 + 净偏差 + 纠偏动作（含最坏延迟下的收敛说明）。判停：τ 完全不可估时，先花一个周期只测延迟不发力。

## B（边界）
- 不适用于近实时反馈场景（τ≈0）——直接闭环纠偏即可，套本卡是过度设计。
- 最坏情况设计有代价：按最坏 τ 设计的动作偏保守，追求极限速度的场景要显式接受这一权衡。
- 时滞足够大时系统必然不稳定（11.6 警告）：此时出路是结构改造（缩短反馈链、就地授权），不是调参——本卡第 4 步的压缩 τ 就是这个出口。
- 区间复盘 ≠ 翻旧账：目的是盘点在途动作，不是追责历史决策。
