# 大系统分解-协调（多级递阶 + 切断重连 + 全局协调必要 + 集中不可能）

## R（原文摘引）
> 离基层单位近的上面的层次或级别是该单位的直接控制中心，只管理或控制隶属于它的一批基层单位的过程并同时采集数据；再上一级可能是负责协调各地区或各类企业之间的相互关系；最上一级负责制定总任务计划和总指标。（第二十一章 21.2）
> 这个方法的基本思想是把大系统划分为若干个子系统，切断各子系统之间的联系，设计控制规律，保证这些孤立子系统具有足够好的稳定性和其它性能，然后把整个系统连接起来，再讨论各子系统之间的耦合关系对全局的影响。（第二十一章 21.5/21.6）
> 这就可能出现一种常见的总体和局部的矛盾：某一种控制作用对一个局部是好的，而从全局来看可能是不好的甚至是不能允许的。如果没有正确的全局性协调……无论每一级的控制如何好，全局性能可能是很不好的，甚至有可能不稳定。（第二十一章 21.2）

## I（解释）
1. **分层的信息论根据**：集中控制实际上不可能——通讯无法瞬时传输全部信息，中心无法加工所有细部数据。多级递阶（执行层直接交付并采集一线数据 / 协调层管跨组依赖与资源 / 决策层定总目标与总指标）不是权力偏好，是信息结构的必然。
2. **分解-协调设计法**：切断子系统间联系 → 各子系统独立设计到足够稳定（各有裕度）→ 重连后专门分析耦合对全局的影响 → 由协调级提供补充信息，把局部控制向改善全局的方向修正。
3. **局部最优 ≠ 全局健康**：各组都达标，拼起来可能震荡甚至发散——必须存在显式全局协调机制（跨组优先级仲裁、共享约束、全局红线），否则分散自治必然以邻为壑。
4. **外模型务实主义**：对得不到精确内模型（结构化状态方程）的过程，宁可用粗但可得的外模型（统计关系：吞吐、周期时间、缺陷密度），不执念于精确建模。
5. **协调可用数学规划**：稳态资源调配类协调问题（产能分配、人力调度）可显式写成约束下的最小总代价问题求解，而不是靠开会砍价。

## A1（原书案例 + 合成演练）
- 原书：地铁检票系统按三级信息处理架构组织（21.4）；地区资源调配写成线性规划求最小总代价（21.9，作者罗列了我国化肥/煤炭/铁路运输的真实应用）；人口发展过程建立定量模型并预测控制（21.3，宋健团队真实研究）；企业指标体系与企业经营列入大系统应用范围（21.1）。
- 合成演练（原书未提供项目案例）：5 团队项目群共享一个平台组 → 分解：各产品团队独立设计交付节奏（各自保证稳定裕度）；重连分析：平台组的接口变更会同时波及 5 团队（全局耦合点）；协调级 = 架构委员会，掌握全量依赖信息，向平台组发"变更窗口 + 冻结期"约束修正其局部最优（平台组单方面追求重构速度对全局有害）；顶层 = 指导委员会只定总指标（交付总量与红线），不看任务细节。检验：若无架构委员会，5 团队各自最优会导致接口震荡——正是 21.2 警告的形态。

## A2（情境应用）
场景：多项目/项目群的治理架构设计时；决定哪些决策上收、哪些下放时；平台团队与业务团队的职责划分时；各组都达标但整体交付仍恶化时。
语言信号：「项目群怎么管」「治理架构怎么设计」「什么决策该上级拍」「各组都挺好的为什么整体不行」「portfolio / governance / 多团队 / 分权」。
区分：decoupling-coordination 管同一层内团队间关系；本卡管整体分层结构与全局协调机制；adaptive-self-stabilization 的分组是按故障恢复设计，本卡分组按治理与信息结构设计。

## E（执行步骤）
输入契约：项目群结构（团队数、共享资源、依赖方向）+ 总目标与全局红线 + 各团队自治程度。
1. 三级分层：定义执行层（直接交付 + 一线数据采集）、协调层（跨组依赖/共享资源仲裁）、决策层（总指标 + 红线），写明每层的输入信息与决策权限。完成标准：三层权责各一行 + 信息流向图。
2. 切断独立设计：各子系统（团队）独立设定目标与裕度，独立验证自身稳定。完成标准：各团队有自己的裕度声明。
3. 重连耦合分析：列出跨组耦合（共享平台、共享人力、接口依赖），逐项判定对全局的影响路径；找出"局部最优动作会伤害全局"的点。完成标准：耦合表 + 冲突点标注。
4. 全局协调机制：为冲突点设协调规则（优先级仲裁、变更窗口、资源配额）；稳态调配类问题写成显式优化（约束 + 最小总代价），可求解则求解，不可解则用规则。完成标准：每个冲突点一个机制。
5. 外模型监控：全局健康用统计性外模型（吞吐/周期/缺陷密度趋势）监控，不要求精确内模型。完成标准：全局仪表盘指标 ≤7 个。
输出契约：治理架构图 + 耦合表 + 协调规则集 + 全局指标清单。判停：团队边界尚在争论时先冻结结构做依赖测绘。

## B（边界）
- 高度集中控制不可行（21.2 警告）：追求"所有信息都到我这、所有决策都我拍"的结构在信息上必然过载失真——但极度分散同样不行（局部最优毁全局），本卡的答案是分层 + 显式协调，不是二选一。
- 分解-协调有适用前提：子系统间耦合相对自身动力学较弱（f ≫ g）时切断法成立；强耦合系统硬拆会两头失稳——先判断耦合强度。
- 分层不是官僚化：层级存在的唯一理由是信息结构（谁离数据近谁决策），多余层级是成本；也要防止协调层膨胀成第二执行层。
- 全局协调机制需要真实权力（仲裁能执行），无权威的协调委员会只是会议。
