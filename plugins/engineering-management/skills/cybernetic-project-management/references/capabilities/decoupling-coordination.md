# 多团队解耦与协调（互不影响设计 + 协调三原则）

## R（原文摘引）
> "互不影响"的控制原则，从物理概念上来说，是利用控制器之间的相互关联完全或部分抵销受控对象中的相互关联，也就是"去耦"，使各个受控量的控制过程不相互影响，从而将多变量关联的大系统分解为单变量"自主"的小系统。（第六章 6.7）
> 如果不具体分析受控对象中固有耦合的利弊，片面要求完全去耦，不仅将使控制系统复杂化，去耦器也难以实现。同时，由于实际对象特性的变化与不确定性，互不影响条件不易准确地得到满足，残留的耦合有可能恶化系统品质。（第六章 6.7）
> 我们所以要把设计条件放在控制矩阵 C 和 C′ 上，是因为在整个系统中只有这一部分是最容易由设计者加以变动的。（第六章 6.3）

## I（解释）
1. **先问要解耦还是要协调**：多变量关系只有两种目标——"互不影响"（各团队独立交付，互不牵连）或"协调"（保持规定关系：节奏同步、比例匹配、接口对齐）。多数组织问题被误诊为解耦问题，实际要的是协调。
2. **解耦落在可变部分**：受控对象（各团队内部实现）与执行机构（人员技能）默认不可改，设计自由度全部放在控制层——接口契约、负责人矩阵、升级机制。解耦条件写成可检验的接口规则，而非"多沟通"。
3. **不盲目完全解耦**：固有耦合先分利弊——有害耦合（互相阻塞、共享资源争抢）切断；有益耦合（共享上下文、互为备份、联调压力）保留甚至加强。片面完全去耦使系统复杂化，且实际中解不干净，残留耦合反而恶化品质。
4. **协调三法**：(a) 协调偏差反馈——各团队目标互为函数（我的验收标准随你的产出动态调整），而非各领死指标；(b) 控制作用间的协调联系——在协调层注入补偿性关联抵销有害耦合；(c) 可测外扰前馈补偿——对可预见的外部变化（大促、监管新规）提前调整，前馈 + 反馈构成复合控制。

## A1（原书案例 + 合成演练）
- 原书：加力燃烧涡轮喷气发动机的转速、喷油速率等三个量互相牵连，通过适当设计尾喷管开口与控制机构，使各受控量的控制互不影响（第六章开篇 + 6.5–6.6，成套设计方法）；机械强迫同步是有益耦合的例子，应利用而非消除（6.7）。
- 合成演练（原书未提供项目案例）：3 个团队共享一个组件仓库 → 耦合分析：A/B 对组件的并行修改互相阻塞（有害，切断：按团队划分所有权 + 接口版本契约）；B/C 的联调互测（有益，保留：协调联系制度化为例行联调节拍）；两端团队发布节奏需同步（协调关系：发布列车 = 协调偏差反馈）。输出：2 项解耦 + 1 项保留 + 1 项协调机制。

## A2（情境应用）
场景：多团队互相阻塞时；接口/依赖治理时；组建平台团队 vs 联邦团队时；跨团队 OKR 对齐时；"要不要把公共组件拆开"的争论时。
语言信号：「团队之间老互相等」「接口怎么治理」「依赖太乱了」「各团队节奏对不齐」「decouple / interface / 依赖治理 / coordination」。
区分：large-system-decomposition 管项目群的整体分层结构；本卡管同一层内多团队间的关系设计；adaptive-self-stabilization 管故障隔离（按扰动范围分组），本卡按交付关系设计。

## E（执行步骤）
输入契约：团队/模块清单 + 相互依赖矩阵（谁阻塞谁、谁共享什么）+ 各自目标描述。
1. 判目标类型：逐对关系标注"应互不影响"或"应保持协调关系"。完成标准：依赖矩阵带目标标注。
2. 固有耦合利弊分析：每条耦合标"有害/有益/中性"及依据。完成标准：无未分析耦合。
3. 解耦设计（只对有害耦合）：在管理层/接口层（可变部分）设计切断机制——所有权划分、版本化契约、变更通知规则；写出可检验条件（"X 变更不需 Y 批准即可发布"）。完成标准：每条有害耦合有一个机制 + 一个可检验断言。
4. 协调设计（对协调关系）：选三法之一或组合——目标互为函数（动态验收标准）/ 协调联系（例行同步节拍）/ 前馈补偿（对已知外部事件预调整）。完成标准：机制 + 触发条件。
5. 残留耦合盘点：没被完全切断的耦合显式登记为已知风险，进监控（feedback-cadence-design）。
输出契约：目标标注矩阵 + 利弊分析 + 解耦/协调机制表 + 残留耦合登记。判停：依赖关系不清时先花一轮只做依赖测绘。

## B（边界）
- 完全解耦既不可行也不必要（原书 6.7 警告）：目标是"有害耦合切断、有益耦合利用"，不是零耦合。
- 解耦有成本（协调开销、去耦层复杂化）：耦合引起的阻塞损失 < 解耦机制的维护成本时，容忍耦合更优。
- 解耦条件会漂移（对象特性变化）：接口契约要定期校验是否仍满足互不影响断言，否则残留耦合恶化品质。
- 不适用于单团队内部协作优化（那是流程问题不是耦合问题）。
