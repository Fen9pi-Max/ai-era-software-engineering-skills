# 基线与偏差管理（摄动制导范式）

## R（原文摘引）
> 实际的火箭的制导问题就是要适当地随时修正升降舵角度的动作程序，设法使实际的射程与标准弹道的射程相同，准确无误地在标准着陆点着陆。……作为初步近似只要考虑偏差的一阶量就够了。这个"线性化"的作法就是弹道摄动理论的基础。（第十三章 13.1/13.2）

## I（解释）
1. **两层结构**：离线用完整信息算一条"标准弹道"（可信基线：范围、里程碑、资源、质量标准全参数已知）；执行期不做全局重算，只度量"实际 − 基线"的偏差并修正。计划的权威性与灵活性由此兼得：基线不轻易动，纠偏天天做。
2. **偏差分析优于重排计划**：偏差出现时问三个问题——偏差多大？沿什么路径传播到终端（哪些里程碑被拖累）？在基线附近一阶外推是否够用？
3. **一阶近似的适用域**：只要实际保持在基线附近，小偏差的传播分析就够用，控制成本极低；偏差增大到"离开标准状态很远"时，线性化失效，必须重定基线（re-baseline）而不是继续修偏差。
4. **偏差管理闭环**：测偏差 → 判传播 → 纠偏或重定基线 → 记录原因（回馈到下一轮基线质量）。

## A1（原书案例 + 合成演练）
- 原书：弹道火箭以预先算好的标准弹道为制导基线，飞行中只测偏差、按摄动方程修正舵偏，使实际落点与标准着陆点一致（13.1，工程设计范例）；标准弹道是"最有代表性的平均弹道"，偏差小是一阶近似合法的前提。
- 合成演练（原书未提供项目案例）：基线 10 周交付、第 4 周末偏差 +1.5 周 → 传播分析：该偏差在关键路径上且后续无浮动可吸收 → 预测终端 +1.5~2 周 → 纠偏选项（并行提效 0.5 周 + 范围降级 1 周）后仍越出验收窗口 → 判定偏差超线性域，启动 re-baseline（新基线 11.5 周 + 范围裁剪），而非继续在旧基线上追。

## A2（情境应用）
场景：制定/冻结项目基线时；周会看偏差时；决定"改计划还是加把劲"时；变更控制委员会决策时。
语言信号：「基线定了还能改吗」「这个偏差要紧吗」「要不要重排计划」「变更怎么管」「baseline / variance / re-baseline」。
区分：model-approximation-identification 建基线模型；本卡管理执行期偏差；multi-objective-tradeoff 决定牺牲哪维指标（纠偏手段的选择）。

## E（执行步骤）
输入契约：已冻结基线（范围/里程碑/资源/质量标准）+ 各期实际数据 + 里程碑间依赖关系。
1. 每期计算偏差向量（进度/成本/范围/质量各维：实际 − 基线）。完成标准：偏差表含方向与幅度。
2. 传播分析：偏差沿依赖链向终端传递的放大/吸收情况（关键路径上放大，浮动路径上吸收）。完成标准：终端影响预测值。
3. 纠偏判定：终端影响在容忍带内 → 实施局部纠偏（不动基线）；越出容忍带或偏差持续单向增长 → 判超线性域，进入 re-baseline。
4. re-baseline 时：新基线必须吸收已知偏差原因（不是简单顺延），经变更控制确认后发布，旧基线归档。
输出契约：偏差向量 + 终端影响 + 处置决定（纠偏/重定基线）+ 原因记录。判停：无基线时先建基线（转 model-approximation-identification）；数据少于 2 期时只记录偏差不预测。

## B（边界）
- 前提是存在可信基线：基线本身拍脑袋时，"偏差管理"是在管理噪声——先回建模卡。
- 一阶近似有适用域（原书明言依赖"偏差总是很小的"）：偏差大而继续小修小补 = 在失效模型上叠加修正，必须换基线。
- 不适用于需求高频变化的探索期项目（基线无意义，转 extremum-seeking-iteration 的滚动试探）。
- re-baseline 是受控事件不是耻辱：频繁重定（>1 次/月）说明计划能力或需求管理有问题，应回根因。
