# 建模与估算（工程近似边界 + 控制量受限 + 辨识三法）

## R（原文摘引）
> 只有当具体的条件和具体的要求明确地给定以后，我们才能把一个实际的系统看作线性系统或是非线性系统。在这个问题上并不存在一般所谓的绝对的判断准则。（第一章 1.4）
> 受控量和控制量不受限制的假定是与实际技术装置的工作情况有一定距离的，这不能不认为是线性理论的重要缺陷。（第一章 1.5）
> 现在常用的方法大致有下列三种：解析法，实验测试法和统计试验法。……应用最广泛和结果最为可靠的是实验测试法。（第一章 1.6）

## I（解释）
1. **简化是决策不是事实**：任何估算模型（"团队速率恒定""需求均匀到达"）都是近似，合法性取决于要回答的问题。先声明"此模型用于回答 X，在 Y 条件下误差可忽略"，再使用。
2. **近似边界触发换模**：问题一旦触及被简化掉的因素（关键人流失、需求突变），模型即失效，必须退回完整分析——不是继续在旧模型上打补丁。
3. **资源硬上限显式化**：一切控制量（人、预算、审批额度、机器）都受客观上限约束。计划中必须列出上限清单；"加人就能赶上"隐含控制量无界假设，是模型错误而非乐观。
4. **辨识三法选型**：解析法（按结构分解推算，WBS 自底向上）适用于可分解且分解后环节不变性的对象；实验测试法（试点/探针任务实测）应用最广最可靠；统计试验法（历史项目数据回归）适用于有积累的组织。分解拼装的环节可能与原环节有质的差别——解析法失效的信号。
5. **实测优先于理论产能**：团队实际吞吐量（观察值）比计划书理论产能（解析值）更可信。

## A1（原书案例 + 合成演练）
- 原书：解析法把复杂系统按结构分解为单元推数学模型，但"分解后的环节可能与在系统中的原环节有质的差别"（1.6）；飞机气动力随速度变化，恒定系数模型只在窄速域内合法（1.2 变系数概念）。
- 合成演练（原书未提供项目案例）：估算新模块工期 → 解析法（按历史同类模块 3 人月）与实验法（2 周探针实测速率折算 4.5 人月）冲突 → 依据"探针含本团队真实联调成本"采信实验值，声明"解析值仅在需求形态与历史高度相似时适用"，输出 4.5 人月 + 边界声明 + 上限（团队 5 人不可扩）。

## A2（情境应用）
场景：做工期/成本估算时；被问"这个简化假设合理吗"时；计划里隐含"资源随时能加"时；历史数据与理论推算打架时。
语言信号：「怎么估这个项目」「这个假设站得住吗」「能不能加点人赶上」「用历史数据还是拆任务算」「estimation / capacity / assumption」。
区分：本卡建模型；baseline-variance-control 用已建模型管执行偏差；extremum-seeking-iteration 处理"连模型结构都未知"的场景。

## E（执行步骤）
输入契约：估算对象描述 + 可用数据（历史项目库/试点机会/结构分解条件）+ 资源约束。
1. 选辨识路径：能做试点 → 实验法；有历史同类 ≥3 例 → 统计法；仅结构清晰可分解 → 解析法；多法并用时以实验/统计为准。完成标准：写出选择依据。
2. 产出模型 + 近似边界声明：模型用于回答什么问题、在什么条件下成立、触及什么信号时失效。完成标准：三问各一句。
3. 列资源硬上限清单（人数/预算/时长/权限），标注每个计划项对上限的占用率。完成标准：任一占用率 >80% 的项标红。
4. 交叉校验：两种路径各出一值，差异 >30% 时分析差异来源而不是取平均。完成标准：差异来源分析或双值并报。
输出契约：估算值 + 置信说明 + 近似边界 + 上限清单。判停：既无历史也无试点机会且结构不可分解 → 如实输出"不可估"，建议先做探针（转 extremum-seeking-iteration）。

## B（边界）
- 不适用于纯创新探索（无结构、无历史、试点代价高）——那里唯一道路是试探迭代。
- 警告（1.6）：解析分解后拼装的环节与原环节可能有质差——WBS 拆得再细，加总也不等于项目工作量，分解推算必须被实测校验。
- 警告（1.5）：忽略控制量上限的计划是理论缺陷不是工程勇气；上限被默认可抬高的计划应整体退回。
- 边界声明不是免责声明：声明后仍需在触及边界信号时真的换模型，否则声明形同虚设。
