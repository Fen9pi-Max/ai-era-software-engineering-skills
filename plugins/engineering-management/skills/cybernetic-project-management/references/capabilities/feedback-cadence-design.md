# 反馈回路与节拍设计（测量-纠偏闭环 + 采样周期 + 告警确认）

## R（原文摘引）
> 凡是在三次或三次以上连续搜索时均发现有目标信号出现时，则认为确实应该发出警报。反之，警报发出以后，若连续四次或四次以上……不出现目标信号时就应该解除警报。（第十七章 17.1）
> 无论系统初始误差状态如何，式(10.6-4)所决定的控制参数将最多在 n 步内使系统的误差归零。或者说任何过渡过程都在 n 个采样周期内结束。（第十章 10.6）

## I（解释）
1. **闭环三要素**：测量（什么信号、什么口径）→ 比较（与基线的偏差）→ 纠偏（谁在多少时间内做什么）。缺任何一环的"监控"只是报表。
2. **采样周期不是越密越好**：节拍过疏（T 大）本身引入额外静差（10.6），过密则把日常噪声当作趋势（交给 noise-filtering-estimation 的带宽权衡）。节拍要与被控量变化速度匹配。
3. **有限收敛检查**：n 维偏差理论上应在有限个节拍内归零（有限拍思想）；若迭代远超维度数仍未收敛，问题在控制律或观测，不在耐心。
4. **告警的双阈值确认**：单次异常不响应。连续 ≥3 个节拍一致异常才升级；连续 ≥4 个节拍正常才解除。触发阈值与解除阈值分别设定（解除更谨慎），N 是虚警率与响应延迟的权衡。
5. **告警要绑定预定义动作**：升级不是"引起重视"，是切换到预设纠偏手段（对照 adaptive-self-stabilization 的开关边界）。

## A1（原书案例 + 合成演练）
- 原书：雷达搜索目标，单次观测有虚警（无目标报有）与漏警（有目标报无）两类错误，用 3 次连续确认触发、4 次连续消失解除（17.1）；离散系统存在控制律使任何初始误差最多 n 个采样周期归零（10.6）。
- 合成演练（原书未提供项目案例）：信号序列 [红,红,红,绿,红,红,红,红]，双阈值 N=3/M=4 → 第 3 拍触发升级，之后仅 1 拍绿色未达解除条件，维持升级。输出与逐拍判定的差异：单阈值法会在第 4 拍误解除、第 7 拍再触发——来回抖动正是要避免的。

## A2（情境应用）
场景：设计项目周报/站会/评审节拍时；定义风险升级规则时（什么条件拉响警报）；"要不要因为这次延期启动应急"的判断；监控体系形同虚设要重设计时。
语言信号：「周报没人看怎么办」「什么情况才升级」「为什么老是在救火」「站会频率多少合适」「cadence / alert threshold / escalation」。
区分：本卡设计节律与升级规则；noise-filtering-estimation 管单次信号的真伪；adaptive-self-stabilization 管升级后切换到什么方案。

## E（执行步骤）
输入契约：被控量清单（进度/缺陷/范围等）+ 其自然变化周期 + 各自的噪声水平（历史波动幅度）。
1. 对每个被控量定采样周期：显著短于其真实变化周期、显著长于其噪声周期。完成标准：每个量有"多久测一次 + 为什么"。
2. 定告警阈值：升级阈值 N、解除阈值 M（M ≥ N+1），N 按噪声水平定——噪声振幅越大 N 越大。完成标准：N 与 M 有数值及依据。
3. 为每级告警绑定预定义纠偏动作与责任人（不是"关注"）。完成标准：告警 → 动作 → 时限三列齐全。
4. 收敛性检查：当前未闭环目标数 n，对照已进行的纠偏节拍数 k；k > 3n 仍未收敛 → 判定控制律失效，转 baseline-variance-control 重定基线或换手段。
输出契约：节拍表 + 告警规则表（触发/解除/动作/责任人）+ 收敛性判定。判停：无历史波动数据时，N 先取保守值 3 并标注"待校准"。

## B（边界）
- 不适用于无法节拍化的连续紧急场景（生产事故响应走事件流程，不套双阈值）。
- N 越大漏警代价越高的场景（安全关键）应调低 N 并接受虚警——阈值是权衡不是模板；原书也只是示例 3/4。
- 告警规则不能替代纠偏手段本身：没有预定义动作的告警体系是噪音放大器。
- 节拍设计的前提是被控量可测；测量质量问题先看 noise-filtering-estimation。
