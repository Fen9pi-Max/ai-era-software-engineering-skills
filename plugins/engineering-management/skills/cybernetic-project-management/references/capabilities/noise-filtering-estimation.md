# 噪声过滤与状态估计（通频带权衡 + 原理性下限）

## R（原文摘引）
> 有用信号的特性与噪声的特性总是有一定的差异，一般说来，有用信号 f(t) 变化比较缓慢，噪声 n(t) 变化比较剧烈。……应该选择一个适当的过滤器，它的通频带既不太宽，又和理想特性差异不太大。（第十五章 15.1）
> 对于这部分叠接频率，分不清观测值中哪些属于有用信号，哪些属于噪声，所以不可能把噪声过滤掉而又同时使有用信号完全通过，因此就不可避免产生过滤的误差。（第十五章 15.1）

## I（解释）
1. **信号与噪声靠特性差异分离**：真实趋势（真实产能变化、需求转向）变化慢；噪声（单日波动、个人状态、口径抖动）变化快。两者时间尺度无差异的量，原理上不可分。
2. **平滑窗口的双向代价**：总均方误差 = 信号失真 + 噪声漏过。窗口短（灵敏）→ 噪声当趋势、过度反应；窗口长（迟钝）→ 真实拐点被抹平、响应滞后。最优窗口取中间值，不是越平滑越好。
3. **原理性下限**：真实进度与日常波动在时间尺度上叠接的部分，无论怎么过滤都分不清——对这部分争论精确没有意义，出路的唯一方向是改善度量本身（换更接近真源的信号），不是更聪明的滤波。
4. **过滤器可能发散**（15.13 警告）：过度信任旧模型、弱化新观测的估计器会缓慢漂移到失效——基线模型要随新数据持续校正，防止"理论最优"实为发散。

## A1（原书案例 + 合成演练）
- 原书：理想微分器对高频噪声无限放大，不可实现；强噪声下的最优预测滤波器宁可牺牲响应速度也要压掉噪声放大项（15.5 例）——最优估计主动放弃"快"。
- 合成演练（原书未提供项目案例）：每日完成点数序列 [12,8,14,9,13,7,15,...] 日均波动 ±3，周均趋势 +0.5/周 → 单日数据噪声占优，任何基于单日的进度判断都在读噪声；按周平滑后趋势可见。若关心"本周是否变慢"，周窗口是灵敏度与噪声的最优折衷；若有人用"昨天只完成 7 点"报警，判定为噪声触发，不升级。

## A2（情境应用）
场景：解读燃尽图/日报/遥测数据时；"昨天数据变差要不要处理"的判断；设定汇报平滑口径时；进度数据打架（工具 vs 说法）时。
语言信号：「昨天进度掉了很多是真的吗」「日报数据怎么这么乱」「燃尽图怎么看趋势」「这个波动正常吗」「signal vs noise / 平滑 / 趋势」。
区分：本卡从含噪观测估真实状态；feedback-cadence-design 用估计结果定升级节律；stability-health-check 判回路发散（结构问题不是噪声问题）。

## E（执行步骤）
输入契约：时间序列数据（≥10 个观测点）+ 已知的常规波动幅度（或可从前期数据估计）+ 要回答的决策问题（关心多快的变化）。
1. 估计噪声底：取无明显事件期的序列，算波动幅度（如标准差）。完成标准：噪声底有数值。
2. 定平滑窗口：窗口 ≥ 决策关心的最短真实变化周期，且窗口内噪声平均后显著小于噪声底。完成标准：窗口值 + 两句依据。
3. 用平滑后序列回答决策问题；单点越出判断为噪声，除非越出幅度 > 2 倍噪声底。完成标准：结论标注"基于 X 点平滑"。
4. 标注不可分辨频段：若关心的变化周期与噪声周期叠接，声明"该尺度上度量原理不可分"，建议改测量（直取真源：验收项数而非点数、交付物计数而非自报）。完成标准：不可分辨声明或改进度量建议。
输出契约：噪声底 + 窗口选择 + 平滑后趋势结论 + 不可分辨频段声明。判停：观测点 <10 时只出"样本不足"。

## B（边界）
- 不适用于事件型突变（生产事故、关键人离职）——那是阶跃信号不是噪声，平滑反而延误响应；突变要靠 feedback-cadence-design 的告警通道。
- 平滑不是为了好看：把一切波动抹平会漏掉真实拐点，窗口选择必须写下依据（第 2 步），不许默认"拉长就好"。
- 原 15.13 警告：估计体系要定期用新数据重校准；长期不更新的基线滤波会发散失效。
- 本卡不做预测（外推），只做当前状态估计；预测性问题另寻方法。
