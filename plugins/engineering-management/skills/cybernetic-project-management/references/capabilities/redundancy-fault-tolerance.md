# 冗余与容错设计（自检 + 重复/备分/k-N + 可靠性口径）

## R（原文摘引）
> 在容错技术中，提高系统工作可靠性的主要方法有两种。第一种是自检，即在系统内发生非致命性故障时能够自动发现故障和确定故障的性质、部位，从而自动地采取措施，更换或去掉这种故障部件。第二是冗余技术，即设置各种备分元器件或组件。（第十九章 19.1）
> 则这个系统的可靠性是 P(t)=R₁(t)·R₂(t)···R_N(t)。由于 R_i(t)≤1，所以系统所含元件越多，它的可靠性就越小。……这叫做 k/N 冗余，数字 N−k 叫做系统（组件）的容错能力。（第十九章 19.2）

## I（解释）
1. **故障分类先行**：致命性故障（不可修复、容错无意义——只能架构性避免）vs 局部/暂时故障（容错对象）。先分类再设计，对致命故障堆冗余是浪费。
2. **串联乘积定律**：全链路成功率 = 各环节成功率乘积。审批链、跨团队依赖、单点人员都是串联——环节越多越脆弱，每环节 95% 时 10 环链路只剩 59%。缩短链路 = 提升可靠性。
3. **冗余三形态**：重复线路（热备——多份同时在岗，一份正常即系统正常，如结对/影子）；备分线路（冷备——平时待命，故障时切换，需要故障发现 + 转接机制：文档 + 交接人 + 触发条件）；k/N 表决（N 份独立输出至少 k 份一致才采纳，如三人独立估算取多数）。
4. **容错能力口径**：N−k = 可同时承受的失效数。要扛住 1 人离职不瘫，需 N−k ≥ 1。
5. **冗余的前提**：各环节故障相互独立且基础质量达标——错误会传染的环节（同一错误同时污染所有副本，如三人抄同一份错的需求）并联反而降可靠性；基础太差的组件堆冗余无效，先修单点质量。

## A1（原书案例 + 合成演练）
- 原书：人脑 10¹⁰ 个细胞中每小时约 1000 个失灵、一生失灵约 10⁹ 个（十分之一）而神经系统终身无故障——靠海量冗余与结构（19 章开篇，生物类比）；冯·诺伊曼证明用不甚可靠的元件可堆积出可靠组件，存在阈值效应（19.3–19.6 数值推算）。
- 合成演练（原书未提供项目案例，公式可复算）：发版链 [代码评审 0.98, 安全审批 0.97, 运维发布 0.99] → 串联可靠率 = 0.98×0.97×0.99 ≈ 0.941；关键模块单人负责（可用率 0.9）→ 设 2/3 表决（两份独立评审 + 一份自动化检查，k=2,N=3）→ 该环节 P = R³+3R²(1−R)（R=0.9 时 ≈0.972 > 0.9），容错能力 = 1。输出：链路瓶颈 = 安全审批（最低环节），与其并联并行审批更划算。

## A2（情境应用）
场景：识别关键单点（人/组件/供应商）时；决定关键角色要不要备份、怎么备份时；多源估算/评审怎么合成结论时；审批链太长老卡壳时。
语言信号：「这个人走了怎么办」「单点故障有哪些」「要不要双人备份」「审批链太长了」「bus factor / single point of failure / 冗余 / 备份」。
区分：adaptive-self-stabilization 管环境剧变后的恢复机制；本卡管元件失效前的结构设计；delay-compensation 管反馈延迟不管元件失效。

## E（执行步骤）
输入契约：关键链路图（环节及依赖）+ 各环节可靠率估计（历史数据或专家估值）+ 失效代价。
1. 串联计算：全链路 P = ∏Rᵢ，找出最低环节。完成标准：P 值 + 瓶颈环节标注。
2. 故障分类：链上各故障点标"致命/局部"。致命 → 改架构（消除单点而非备份）；局部 → 进第 3 步。
3. 冗余选型：按失效代价与响应速度要求选形态——需无缝接续 → 热备（结对/影子/双活）；可容忍切换时间 → 冷备（文档+交接人+触发条件写明）；多源判断 → k/N 表决。完成标准：每个局部故障点一种形态 + 理由。
4. 独立性检验：冗余副本是否真正独立（不同人/不同数据源/不同时段）？同源副本标注"伪冗余"不计入容错能力。完成标准：独立性判定。
5. 定容错能力需求：要承受的同时失效数 → N−k ≥ 该数；对照成本排出优先级，先补串联乘积中最薄弱环节。
输出契约：链路可靠率 + 瓶颈 + 冗余方案表（形态/触发/独立性）+ 容错能力数值。判停：可靠率数据完全缺失时，先按 0.9–0.95 假设值计算并标注"待校准"。

## B（边界）
- 冗余不是万能药（19.2/19.5 精神）：错误传染时（同源污染、级联失效）并联反而更糟；基础质量低于阈值的环节先修质量再谈冗余。
- 各元件故障须相互独立——三份拷贝同一份错误文档不是 3 倍可靠，是 1 倍。
- 冗余有真实成本（人力/授权/维护）：失效代价低的环节不值得冗余，让流程兜底即可。
- 冷备依赖"发现 + 转接"：没有演练过的备份计划视同不存在，切换机制要定期演练。
