## I（解释）

OKR 是员工对经营高层一个问题——"对于我们这样一个公司，你能做出哪些贡献？"——的回答：由员工**自主设定**，但方向必须挂在经营层的宏观目标上，不能脱离整体框架。团队、部门层面同样要回答这个问题。

好的 OKR 有五条硬标准：① 战略目标与可测量的具体目标融合；② 有野心——完成度 70% 的 OKR 最用心，100% 完成恰恰说明目标太敷衍（谷歌口径）；③ 全员实践并通过面谈定期反思；④ OKR ≠ 考核——得分不作直接评价，员工才敢坦诚反思（可按目的与考核结合：重业绩就把完成得分作参考，重态度就把工作态度数值化后加入）；⑤ 聚焦最重要的目标，不铺满所有工作。写法上再过一遍 SMART：具体/可测量/可达成/相关/有期限。

与 KPI 的分工：KPI 自上而下（目标销售额、客户访问次数），OKR 自主设定、以过程中的反思和调整为前提，两者并行不互斥。

内容质量靠 10× 倒推把关：不问"提高百分之多少"，问"怎样把业绩扩大 10 倍"，从公司利润的整体目标倒推——财务团队的正例不是"维护费用报表流程"，而是把"去除费用报表手工制作"设为季度 OKR（去除工作=减少成本=增加利润）；销售团队除销售额外还要加获取新客户、内部人事项目。把日常流程设成目标，永远等不来效率的飞跃。

运行节奏三件套：季度初公司先定调；OKR 全员公开可查（谷歌用 Google Docs 共享，彼此看得到进展，就不猜忌、没人怀疑别人偷懒）；每周 1on1 检视进展，发现某项 OKR 没有意义，立刻建议放弃。

## A1（原书案例 / 合成演练）

**案例一：财务部 OKR 倒推（worked_example，第6章 ◆如何制定高效OKR）**。输入：财务团队，惯性认知是"我们是财务团队，每天只能坐在工位上制作费用报表"；反面做法是把日常工作流程或基本操作直接设成目标（作者诊断：日本很多大企业的 OKR 因此背离初衷）。执行（书中对话）："费用报表太费事了，咱们应该把手动制作改成用系统录入和整理。""这个主意不错。那就把思考怎样才能去除费用报表制作的工作作为这个季度的OKR吧。"结论：OKR 从实现公司利润的整体目标倒推；去除本团队的某些工作等于减少业务成本、增加整体利润。该季度实际完成度未说明。

**案例二：每周 1on1 检视与弃用（firsthand，第6章 好的OKR具备哪些特点）**。输入：作者任职谷歌期间所带的团队 OKR。执行：利用每周一对一面谈逐项讨论 OKR 进展；发现某项 OKR 没有意义，就建议成员立刻放弃。结论：OKR 以工作过程中的反思和调整为前提，弃用是机制的一部分而非失败。具体被放弃的 OKR 实例与结果未说明。

**案例三：销售团队的 10× 设定（worked_example，第6章 ◆如何制定高效OKR）**。输入：销售团队的季度 OKR。执行：除季度销售目标外，加入获取新客户、内部人事项目等附加内容。结论：对销售团队来说 10× 就是必须创造新价值；只把销售额设为 OKR，恐怕很难提高效率。未说明结果。

**案例四：OKR 公开共享消除猜忌（reported_case（谷歌实践），第6章 "自动化和模式化"也能增强安全感）**。输入：全员 OKR 的可见性问题。执行：OKR 上传完全系统化，团队在谷歌文档（Google Docs）上共享，成员可随时查看自己和他人负责工作的进展。结论：成员之间不会彼此猜忌，也没人怀疑别人偷懒——公开本身就是安全感机制。未说明量化效果。

## A2（情境应用）

**触发场景**：
- 季度初要为团队或个人定 OKR，手里只有公司一句战略口号，不知怎么落成目标；
- 从 KPI 转向 OKR 的团队，写出来的"OKR"看起来就是岗位职责清单（每天完成巡检、每周出报表）；
- 1on1 里过目标进展，某项 OKR 已经明显没有意义，纠结"定了的还要不要坚持"；
- 复盘时发现 OKR 连续几个季度 100% 完成，团队却没变化；
- 管理者想确认成员的目标是否与公司方向一致。

**语言信号**：
- 中文：OKR、目标与关键成果、季度目标、关键结果、KR、SMART、10 倍、野心目标、目标对齐、目标太保守、KPI 和 OKR 的区别、目标复盘
- 英文：OKR, objective and key results, quarterly goals, key results, SMART goals, stretch goals, moonshot, 10x, KPI vs OKR, goal setting, commitment review

**与相邻能力的区分**（初稿）：
- 与 stm-mechanism-design（U15）：本能力管"OKR 内容怎么定、怎么校验"；U15 管"OKR 作为一项机制怎么运转"（公开共享的载体、1on1 制度、纳入自动化模式化清单）。要建整套制度走 U15，写本季目标走本卡。
- 与 stm-experimentation-speed（U12）：U12 管"推进节奏"（草案、试探、弃计划的心态）；本卡是季度目标层的结构化方法。目标本身定错（如流程维护）时用本卡重写，而不是靠 U12 加速执行。
- 与一对一面谈能力（U03/U13）：本卡只占用 1on1 的"OKR 检视"这一个议程；1on1 怎么开、聊什么（成员主导、价值观提问）归 U03。
- 与 stm-subtraction-evaluation（U11）：考核口径（业绩+行为双轨、减法）归 U11；本卡红线是 OKR 得分不直接进考核，最多作参考。

## E（可执行步骤）

**OKR 制定流程：公司目标对齐 → 10× 倒推 → SMART 校验 → 野心校准 → 公开登记 → 周检视 → 季度弃用复审**

1. **公司目标对齐**。获取本季度经营层制定的公司 OKR（或使命/愿景/商业模式表述）；写下"对于我们这样一个公司，你能做出哪些贡献？"的回答初稿。完成标准：每条候选 OKR 都能指出它与公司目标的关联点；拿不到公司目标时先向上获取，不静默自造。
2. **10× 倒推（判停点）**。对每条候选问两个问题：达成后业务会发生什么实质变化？它是否从公司利润/整体目标倒推而来？把"维护/照常执行某流程"式目标清除，改写成"去除/创造"式目标（财务团队参照：不是"做好费用报表"，而是"去除费用报表手工制作"）。完成标准：每条 OKR 通过"实质变化测试"——若照常运转也能 100% 达成，重写。**判停点：候选清单里全是流程维护目标 → 停止校验，回第 1 步重新倒推**。
3. **SMART 校验**。逐条过五关：S 所有人都能看懂要做什么；M 可转化为数值；A 通过努力可达成（难度不过小或过大）；R 与组织及团队目标相关；T 有期限（季度内限期完成）。完成标准：五项逐条标注通过/改写，未通过项当场改写后重过。
4. **野心校准（70% 口径）**。自评"全力以赴情况下的期望完成度"：约 70% 为最佳用心区间，预期 100% 完成的目标判为太敷衍、调高难度（谷歌口径，见 B 段标注）。完成标准：每条 OKR 附一个"预期完成度"估计值，处于约 60%–80% 区间（原书仅给 70% 单点口径，60–80 为本卡约定容差，不改变原意）；不达标的目标重新拔高或合并。
5. **公开登记**。把 OKR 登记到全员可随时查看的位置（共享文档即可；谷歌做法是 Google Docs 共享）。完成标准：登记位置对全团队可访问，含负责人、指标基线、期限。
6. **周检视**。纳入每周 1on1 议程，逐项过进展与阻碍。完成标准：每周留检视记录（进展/阻碍/下一步），无"定完就锁抽屉"的 OKR。
7. **季度弃用复审**。1on1 中发现某项 OKR 没有意义 → 当场建议立刻放弃并记录理由；季度末对每项做 完成/继续/放弃 复盘。完成标准：每项 OKR 季度末有明确去向与理由记录。

**输入契约**：必需 = 公司季度 OKR 或经营层宏观目标表述（缺失须先向上获取，不静默猜）；团队职能与关键指标的当前基线（用于 M 与 A 校准）；公开登记位置。可选 = 与考核结合方式的事先声明（二选一：完成得分作业绩参考 / 工作态度数值化后加入，见 B 段红线）；上季度 OKR 复盘记录。

**输出契约**：OKR 草案，每条含 Objective + 若干 KR，字段为：目标描述（S 通过）/ 量化指标与基线（M）/ 期限（T）/ 与公司目标的关联（R）/ 预期完成度（约 70% 口径）。另交付：合格 OKR 检查表（下表逐项打勾）、公开登记链接或位置、周检视记录模板（进展/阻碍/下一步）、季度弃用决定记录（继续/放弃+理由）。

**合格 OKR 检查表**（五组逐项通过方可登记）：

| 检查组 | 项目 |
|---|---|
| 5 个关键 | 战略+可测量融合 / 有野心（预期完成度约70%）/ 全员实践+面谈反思 / OKR≠考核 / 聚焦最重要目标 |
| SMART | 具体 / 可测量 / 可达成 / 相关 / 期限 |
| 落地 5 注意 | 季度初公司先行对齐 / 公开可查 / 定期 1on1 回顾 / 与考核结合方式已声明或不结合 / 组织支持氛围 |
| 10× 倒推 | 非流程维护目标；达成后业务有实质变化 |
| 弃用规则 | 周检视中无意义即弃的通道已在 1on1 议程中 |

## B（边界）

**反场景（何时不用）**：
- 纯合规指标场景（法定报表、安全 SLA 的刚性 KPI）——这类自上而下指标本身没问题，按 KPI 管理，OKR 与之并行而非取代；
- 一次性事务或短周期杂务的目标（两周内的一次活动筹备）——用前馈/复盘即可，不够一个 OKR 周期；
- 团队尚未有基本信任与安全感时直接上"全员公开 OKR"——公开会把弱点暴露变成风险，先补安全感基础（见五要素诊断能力）；
- 把 OKR 用于直接考核或排名——见下方失败模式 ce-58。

**书中警告的失败模式（含候选反例 id）**：
- ce-57 把 OKR 设成日常流程维护（财务部反例：把"每天制作费用报表"的流程设成目标；OKR 列的是岗位职责清单）；
- ce-58 OKR 得分直接当考核（员工无法坦诚反思，激励倒向"定保守目标+粉饰进展"，70% 野心机制失灵）；
- ce-59 保守 OKR（100% 完成度 = 目标敷衍；连续几季度全部达成是警报信号）；
- ce-02 只对齐直属上司不对齐经营者（员工 OKR 必须与经营层宏观目标方向一致，不是揣摩上司偏好）。

**作者盲点/时代局限**（阶段 0 批判 + needs-review 标注）：
- "完成度 70% 最用心 / 100% 太敷衍"是谷歌实践口径，其他类型组织未经外部验证（nr-09），作为校准启发而非硬公式使用；
- OKR 与考核结合的具体方法书中只举"业绩得分参考/态度数值化"两例，细节未展开（阶段 1.5 已标 missing_conditions），落地须自行补规则并事先向成员声明；
- 全员公开、全公司周报级共享以谷歌的大组织透明文化为前提，小团队或涉密团队需降配公开范围，但"团队内公开可查"这一最小形态应保留。
