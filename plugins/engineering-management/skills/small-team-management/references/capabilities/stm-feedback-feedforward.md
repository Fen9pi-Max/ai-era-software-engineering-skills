# 反馈与前馈循环

## R（原文摘引）

> "前馈则不同，它不是工作完成之后的总结，而是在开始工作之前进行的沟通。比如'你打算为这项工作做哪些准备？''我打算这样准备。''那你恐怕漏掉了××。这种风险最好提前做好防范措施，否则搞不好会出大问题。你看呢？'"（第4章 变"反馈"为"前馈"）

> "当然，我并不是说不需要反馈。我想说的是，只有能体现到下一次前馈中的反馈才有意义。"（第4章 变"反馈"为"前馈"）

> "成员当天完成的内容尽量当天讨论，最好能当场给予反馈，这个环节非常重要。管理者为此需要坚持每天与下属交流，这就是教练。我反复强调'每一个瞬间'，指的就是这一点。"（第4章 ◆随时反馈，越快越好）

> "不过在比赛中，教练不会给出反馈或建议，因为这会让运动员不知所措。到了休息时，教练会酌情做出简短指示，这也属于实时判断。工作中的团队要获得成功，也离不开这种灵活及时的精准指令。"（第4章 ◆团队成功离不开灵活及时的指令）

> "我建议管理者要先把自己的'判断标准'公之于众。我对待成员有一个标准，那就是找我讨论工作时，他们必须要拿出'能推进下一步工作的预案'。……比如你可以拟出A、B、C三个方案，让我选择哪个更好，或者先让大家看看，其他人都觉得可以了再来找我确认。"（第4章 提前把标准告诉成员 / ◆规则可以避免浪费时间）

> "管理者可以用符合逻辑、具有建设性的方式表达自己的看法：'我觉得这个地方可以这样改''这方面没有数据支撑，我觉得不太有说服力。'……还有一种敷衍的回答也很成问题，比如'嗯，不错'。"（第3章 开放式沟通是新创意的摇篮）

## I（解释）

这套方法把"管理者给反馈"重构成一个**以前馈为轴的循环**，而不是事后的单向点评。

**前馈**是工作开始前的沟通：先问"你打算为这项工作做哪些准备"，再对照自己掌握的信息指出对方漏掉的风险（"那你恐怕漏掉了××，最好提前防范"）。价值在预测结果、提前调整行为，比事后复盘便宜得多。

**反馈**没有被取消，但被加上一条硬性检验：**只有能体现到下一次前馈中的反馈才有意义**。复盘得出的每条教训，必须落成下一轮开工前的风险项或准备项，否则问题必然重演。

时效上要求**当天化**：成员当天完成的内容当天讨论、最好当场反馈——反馈延迟越久，错误固化越深、指导价值越低。

节奏上借用教练-运动员模型：**训练（日常工作）随时给具体反馈；比赛（关键执行）不给反馈、只给简短明确指令；休息（间隙）酌情指示**。执行中途的纠正性反馈会让执行者不知所措。

入口处立规矩：把判断标准**公之于众**——来讨论必须带"能推进下一步的预案"（A/B/C 三方案，或先过其他人再确认）。无预案的讨论不改变任何状态，只是消耗双方时间。

质量上：反馈必须**具体、有逻辑**（"这个地方可以这样改""这方面没有数据支撑"），"嗯……我也说不好"和"嗯，不错"这类不置可否的敷衍等于把优化成本退回给成员。

## A1（原书案例 / 合成演练）

**案例一：新人制作资料的全程教练（worked_example，第4章 ◆随时反馈，越快越好）**。输入：新人 + 一份资料制作任务。执行：不甩"明天下班前做完"，而是先一起做（"这是××项目要用的资料，你觉得应该怎么做？"）→ 肯定其思路并补增量（"按你的方法这部分能完成得很好，不过要提供更多价值还要加上这个部分"）→ 指引信息来源（"你搜索这个关键词，先看一看，然后我们再讨论"）→ 降门槛（"不用追求完美，今天先做一份初稿就行"）→ 初稿当场点评（"这个视频很有意思，这张图用得也很妙。如果把文案再这样改一下，应该会更好一些"）。结论：示范"随时反馈+当天反馈"的完整链路（结果未说明，为操作示范对话）。

**案例二：未来论坛的前馈闭环（firsthand，第4章 变"反馈"为"前馈"）**。输入：作者每月举办的职场活动 MIRAI FORUM。执行：活动前与成员一起以前馈形式出谋划策 → 活动结束后马上开会（"大家来说说这次活动中有哪些成功的和不太成功的部分"）→ "那咱们再一起想想，下次怎样才能避免这种情况"。结论：已交代——"这些反馈的结果会自然而然地体现在下一次活动的前馈中"，业绩在及时前馈与反馈的积累中提升。

**案例三：残缺初稿被退回（worked_example，第4章 ◆规则可以避免浪费时间）**。输入：成员拿来"初稿的初稿的初稿"，粗略到无法反馈。执行：退回并说明标准——"按照现在这个情况，咱们讨论不出任何结果。你要占用我的时间，就应该先把初稿做好。比如你可以拟出A、B、C三个方案，让我选择哪个更好，或者先让大家看看，其他人都觉得可以了再来找我确认。"结论：作者表态"我想我会像这样让他把初稿拿回去重做"（预期行为，实际结果未说明）。

**案例四：三次"把这里改一下"的空转（reported_case，第4章 ◆规则可以避免浪费时间）**。输入：日本大企业常见一幕——成员交粗糙草稿，管理者指示"把这里改一下"；第二次又"把这里再改一下"；第三次"嗯，做得不错"。结论（作者判定）："这样的沟通不可能提高团队效率"——标准不公开，成员只能逐次试探，双方时间被返工循环吃掉。

**案例五：谷歌高管收下不完善的方案、不再约见（reported_case，第4章 ◆规则可以避免浪费时间）**。输入：员工把不够吸引人的方案拿给谷歌高层。执行：高层不要求修改，只随意收下资料；因约不到下一次见面时间，这项工作便不会再有机会讨论。结论：这是谷歌的常识性信号——"你还需要继续努力，有了更吸引人的方案再拿给我看"；占用高层时间必须拿出让其感兴趣的方案，否则就是浪费双方时间。

## A2（情境应用）

**触发场景**：
- 成员即将开始一项重要工作（客户演示、方案交付、活动组织），你想把问题消灭在开工前；
- 成员刚交出成果，你在想这次怎么给反馈才不流于形式；
- 同样的失误在成员身上反复出现，复盘开了却没有变化；
- 成员空手来问"这个怎么办"，你既不想当答案机、又不想显得冷漠；
- 关键执行进行中（上线日/客户会议中），你发现成员的做法有问题，纠结要不要当场纠正。

**语言信号**：
- 中文：反馈、前馈、复盘没有用、怎么给下属反馈、当天反馈、改了三次还在改、空手来问、无预案不讨论、进展会空转、返工循环、评完就完了
- 英文：feedback, feedforward, performance feedback, debrief, retrospectives not working, how to give feedback to direct reports, same mistake twice, empty-handed questions, rework loop

**与相邻能力的区分**（初稿）：
- 与 stm-subtraction-evaluation：本能力管**单件任务级**的日常反馈/前馈闭环；季度/正式评价的打分口径（业绩+行为双轨、减法）归减法评价。评价面谈中的行为反馈话术在减法评价。
- 与 stm-one-on-one-coaching：本能力给出反馈的时机与结构；1on1 这个场合谈什么（价值观提问、职业规划）归一对一面谈。当天反馈常发生在 1on1 之外的工作现场。
- 与 stm-reflection-rhythm：三次反思是**管理者自己**在会前/会中/会后的反思节律；前馈是管理者与成员就**具体工作**的双向沟通。二者可叠加但对象不同。
- 与 stm-complaint-conversion：成员失误后的"出了什么问题/今后怎么避免"三问与失误汇报应对归抱怨转换；本能力管的是主动给出反馈的前-中-后结构。

## E（可执行步骤）

1. **事前前馈（任务开始前）**。对成员即将开始的工作执行三段模板：
   ① 准备询问："你打算为这项工作做哪些准备？"（先让对方说，不先入为主）；
   ② 风险预判：对照自己掌握的信息（历史坑、客户偏好、资源约束）指出对方漏掉的项——"那你恐怕漏掉了××"；
   ③ 防范措施：对每个风险约定具体防范动作，记入该任务的前馈记录。
   完成标准：前馈记录含成员自述准备清单 ≥1 条、管理者补充风险 ≥1 条、每个风险对应一条防范措施。**输入为空（成员说不出任何准备）→ 先陪跑第一步（参照 A1 案例一），不直接替对方列清单。**

2. **执行中按时机干预（教练-运动员模型）**。判定当前阶段：训练段（日常工作/练习性交付）→ 随时给具体反馈；比赛段（关键执行窗口：客户在场、上线、限时演示）→ 不给反馈，只给简短明确指令；休息段（间隙/复盘窗口）→ 酌情简短指示。完成标准：比赛段内没有发出纠正性反馈（发现的纠正点记下来留到休息段）；指令句式短、可执行。

3. **当天反馈（完成/交付当天）**。三段模板：
   ① 亮点具体化：指名道姓到具体元素（"这张图用得妙"级别），禁用"嗯，不错"；
   ② 一处改进：用"我觉得这个地方可以这样改 / 这方面没有数据支撑"式有逻辑的表达，一次只提一处；
   ③ 写入下次前馈：把改进点转写为该成员下一轮前馈记录的风险/准备条目（"下次怎样才能避免这种情况"）。
   完成标准：反馈记录三段齐全；改进项能在下一次前馈记录中找到对应条目（这是"只有能体现到下一次前馈中的反馈才有意义"的可检验形式）；全文检索不到无信息量的敷衍语。

4. **公布标准 + 处理无预案求助（入口规则）**。对每位成员（首次合作时）公开判断标准："找我讨论工作，必须拿出能推进下一步工作的预案——A、B、C 三个方案让我选，或先让其他人看过、都觉得可以了再来找我确认。"收到无预案求助时的话术：先问三连——"你想通过讨论从我这里得到什么结果？让我发表意见？做决定？拨预算？"→ 若答不出或确无预案："按照现在这个情况，咱们讨论不出任何结果。你要占用我的时间，就应该先把初稿做好。比如你可以拟出A、B、C三个方案让我选择，或者先让大家看看，其他人都觉得可以了再来找我确认。"完成标准：标准已向全员公开 ≥1 次（口头或书面）；每次退回时成员带走的路径是三选一（A/B/C 方案 / 先过他人 / 说明想获得的结果）之一。

5. **判停点：连续退回**。同一成员连续两次带预案来仍无法推进讨论 → 问题大概率不在成员（标准传达不清或任务超出其当前能力），停止继续退回，转做：重述标准并示例一份合格预案，或按情境领导降档改用指导/指令模式陪跑一轮，再回到第 1 步。

**输入契约**：必需 = 一件具体工作（任务描述 + 时间点：即将开始 / 进行中 / 当天完成）+ 执行成员。可选 = 该成员上一次前馈记录、任务相关的风险背景、成员能力意愿定位（用于第 5 步降档判断）。缺时间点 → 先确认工作处于哪个阶段，阶段决定走第 1/2/3 步，不能跳步。
**输出契约**：任务级前馈记录（准备清单 + 风险 + 防范措施）；当天反馈记录（具体亮点 ≥1、改进点 1 处、转入下次前馈的条目 1 条）；无预案求助的退回话术记录。闭环判据：任意一次事后反馈的改进项，在下一次前馈记录中可检索到对应条目——做不到即视为"只反馈不前馈"，回到第 3 步③补作业。

## B（边界）

**反场景（何时不用）**：
- 正式季度/年度评价、打分与总评 → stm-subtraction-evaluation（本能力是任务级日常闭环，不打分）；
- 成员带着抱怨或汇报失误来找你 → 当下先用 stm-complaint-conversion 的接发球/失误三问，前馈结构适用于其后的行动准备；
- 1on1 里的职业规划、价值观深谈 → stm-one-on-one-coaching；
- 一次性、无下一轮的工作（已下线项目的一次性交接）→ 没有下一次前馈可承接，走普通复盘即可。

**书中警告的失败模式（含候选反例 id）**：
- 甩手式交办新人：一句话"明天下班前做完"抛出去、零过程交流（ce-36）；
- 只反馈不前馈：复盘以"这次失败了，这个部分没做好"收尾，无"下次怎么办"（ce-37）；
- 情绪化发飙应对"成员不听指令"，不检查标准是否公布（ce-38）；
- 标准私有化：不公布判断标准，任由成员在"把这里改一下"×3 中试探（ce-39）；
- 接受无预案求助："什么都没做就来问我应该怎么办"照单全收（ce-62）；
- 含糊敷衍反馈："嗯……我也说不好""嗯，不错"，无信息增量（ce-27）。

**作者盲点/时代局限（阶段 0 批判 + 使用约定）**：
- "当天反馈"以物理同处、每日面对面为前提；远程/异步团队需约定等效时窗（如 24 小时内书面反馈），此为约定而非原书规则；
- 谷歌高管"收下不完善方案、不再约见"是高流动性人才市场+强文化共识下的隐性信号，普通团队直接模仿极易被解读为冷漠或漠视——书中也承认该信号需以"占用高层时间须拿出让其感兴趣的方案"的公开常识为前提；照搬前务必先完成第 4 步的显式标准公布；
- 前馈在书中只有对话示例、无结构化模板，本卡 E 段三段模板（准备询问→风险预判→防范措施 / 亮点→一处改进→写入前馈）是按原书要素的约定组装，已验证不改变原意；
- "比赛时不反馈"来自体育类比，知识工作的"关键执行窗口"边界模糊，按"客户在场/不可逆操作/限时交付"近似界定（约定）。
