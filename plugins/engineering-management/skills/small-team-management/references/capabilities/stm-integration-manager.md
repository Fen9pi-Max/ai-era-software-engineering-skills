# 整合型管理者与做减法

## R（原文摘引）

> "谷歌的团队管理者也是参与型管理者，而且忙碌程度不亚于日本企业的管理者。不过二者之间有一个本质区别，就是谷歌的团队管理者不会与团队成员做同样的工作。我要再次强调，他们只参与同级别团队内的工作，比如组长做组长级别的工作，科长做科长级别的工作。"（第5章 ◆谷歌式"参与型管理者"）

> "新时代的管理者需要调动公司内外的一切资源，创造出最佳组合。也就是说，只有成为“整合型管理者”，推翻现有流程、大胆尝试外包业务或新型技术，才有可能大幅提高效率。"（第5章 ◆做一个"整合型管理者"）

> "日本式参与型管理者常见的误区就是认为如果团队有5个成员，就必须把5个人都用上。"（第5章 ◆做一个"整合型管理者"）

> "管理者把工作委派给成员，相当于为成员提供了学习的机会。在工作中学习具有重要意义，相反，如果学不到新东西，工作的价值就比较低。从这个意义上看，把工作交给成员对管理者也有益处。因为重复性工作减少了，管理者自己就能拥有更多的时间用来学习了。"（第3章 ◆把学习机会留给团队成员，也留给自己）

> "简单来说，是为了管理者不在现场时，工作也能照常运转。也就是为了帮助管理者减少自己手上的工作，腾出精力去考虑其他问题。"（第6章 管理者的工作就是减少自己的工作）

> "管理者的职责不是自己做出业绩，而是要做出各种判断，最大限度地提高团队成员的业绩。因此在谷歌任职期间，我对自己团队成员的要求是“不要自己什么都没做就来问我应该怎么办”。"（第6章 ◆成员的成果决定了管理者的业绩）

## I（解释）

这张卡回答"管理者本人到底该做什么"。书中给出三级跳：**日式参与型 → 谷歌式参与型 → 整合型**。日式参与型与成员做同样的日常工作，忙得团团转；谷歌式参与型不做本团队的日常，而是加入同级管理者组成的团队、以成员身份做本层级的工作（做会议记录、写策划书）——因为管理者的安全感来自上一级团队，"孤狼"在谷歌评价极低。整合型再进一步：管理者的职责是围绕团队要创造的价值，随时组合公司内外的人才、技术、流程——请咨询、招临工、用众包、上新技术——而不是顺从现有推进方式。"团队有 5 个人就必须 5 个人都用上"是典型误区：不创造价值的成员应调去能贡献的舞台，改进流程后 3 个人可能更高效。判断标准用教练比喻最清楚：教练不上场踢球，把球员当助理、自己踢基层的活，是对管理岗的零和占用。

做减法有两台发动机。一是委派循环：委派不是甩活，而是给成员学习机会（学不到新东西的工作价值低）；对新人说"试试看"而不是"对你还太早"。委派同时把管理者从重复性工作里解放出来去学新东西——双向都是学习。二是机制化：在人才、技术、流程上建机制，让管理者不在场团队也照常运转——"管理者的工作就是减少自己的工作"。

配套两条纪律：其一，以身作则——管理者自己不踏出第一步（第一只企鹅），就不会有人跟上来；新事物（如众包）要自己先开创先例。其二，警惕团伙化——运转团队为了自己而非公司的管理者（爱自夸、爱抱怨、拉帮结伙、挖人创业）终将失去信赖，团伙式创业基本失败。业绩的最终口径也随之翻转：管理者不自己造业绩，而是做判断、放大成员的业绩；成员求助必须带初步方案——"我想了三个选项，您觉得哪个最好"，不空手来问。

## A1（原书案例 / 合成演练）

**案例一：亚太主管的双团队工作法（firsthand，第5章 ◆培养好下属才能挑战其他工作）**。输入：作者任谷歌亚太地区人才培训部门主管，同时是全球人才培训主管团队的成员。执行：本团队——把亚太地区绝大部分工作委派给下属（仅保留人才部署、工资奖金分配等不可交办事项）；上级团队——与欧洲、美国主管协商制定全球人才培养战略。结论：不委派就没有精力做全球团队的工作；下属通过被委派的工作提升了技能与职业经历，成为"下一代管理者"；团队具体绩效未说明。

**案例二：沃兹尼亚克与乔布斯——第二只企鹅（reported_case，第5章 开创先例，以身作则）**。输入："第一只企鹅"比喻率先跳入海中的行动者——领头企鹅冒险跳海，群体才会接二连三跟上。执行：据考证第一只企鹅可能是被后面的企鹅推下去的——"第二只企鹅"（助推者）或许才是真正的领导者；苹果创业之初，沃兹尼亚克犹豫不决，在乔布斯力邀下才下定决心。结论：乔布斯看似第一只企鹅、实属第二只企鹅类型——管理者的启示是只要自己时刻走在最前面，第二只、第三只企鹅就会出现（who 推 who 的考证为作者转述轶事）。

**案例三：团伙管理者的挖人创业（firsthand 见闻，第5章 ◆"团伙化"管理者的特征，反例）**。输入：作者在外企目睹的多起案例。执行：团伙管理者爱自夸（"你瞧瞧别的团队，什么活儿都不干！"）、爱抱怨、用"一起喝酒去！"拉帮结伙、招揽言听计从的部下，最后挖走成员自己创业。结论：工作能力无可挑剔，但经营只为自己的目的会逐渐失去信赖，靠团伙方式创业基本以失败告终，在日本（推崇利他的沟通文化）尤其行不通（个案后续未说明）。

**案例四："不空手来问"的团队沟通规则（firsthand 规则实例，第6章 ◆成员的成果决定了管理者的业绩）**。输入：作者对谷歌自己团队成员的要求。执行：求助必须自带初步意见——"我想了三个选项，请问您觉得哪个最好""我做了一份资料，请您过目，重点部分在这里"。结论：管理者由此获得可判断的输入，也能对外分享有助于提升成员与团队口碑的信息；无方案的求助既无从判断也无从分享。

**案例五：品牌业务众包（firsthand，第5章 ◆团队众包日趋重要，兼 U09 素材）**。输入：作者公司把与品牌相关的业务外包给一位外部人士打理。执行：不承担昂贵的固定工资费用，运用外部资源在短时间内产出成果、完成很多重要工作。结论：整合型管理者的"调动外部资源"实例；具体 ROI 未说明。

**案例六（合成演练）：管理者工作四桶分类**。原书未提供完整的时间审计表，以下按原书规则合成。输入：某管理者每周 50 小时中约 30 小时在做本团队一线交付（写代码/做方案），下属 5 人。执行：列出全部工作 → 四桶分类——成员能学的（一线交付大头）委派出去并明示"这是学习机会"；可机制化的（周报汇总、常规提醒）自动化；可外包的（设计、内容排版）评估众包；必须自己做的（1on1、考核、上级团队会议）保留。复算：管理者每周腾出约 20 小时转入同级管理者协作与长期规划。验收：连续两周休假日团队照常交付。说明：桶划分与小时数为演练假设，规则本身（委派/机制化/外包/保留四去向）出自原书。

## A2（情境应用）

**触发场景**：
- 管理者的日历被本团队一线任务填满，下班后才有空"做管理"，感到工作"很烦琐、没意思"；
- 团队离开管理者就无法运转——请假一天交付就停摆；
- 反复听到"人手不够，必须再招 N 个人才能干这件事"，从未讨论过外包、众包或技术替代；
- 想培养下属/下一代管理者，但"教他做比自己做还慢"，纠结要不要把活收回来；
- 观察到某位同级管理者爱自夸、拉帮结伙、暗示成员跟他出去创业。

**语言信号**：
- 中文：事必躬亲、参与型管理者、我的人手不够、5个人必须都用上、委派、放权、授权成员、教练不下场、把成员当助理、团伙、挖人创业、管理者的业绩
- 英文：playing manager, integrator manager, delegation, empowerment, outsourcing, crowdsourcing, doing less as a manager, manager as coach not player, manager's job is to reduce their own work, team runs without the manager

**与相邻能力的区分**（初稿）：
- 与 stm-team-composition（U09）：本能力管"管理者自己做什么、不做什么"的角色转型与时间配置；U09 管"团队由谁组成、多大、怎么流动"。转型的分类结果（需要招人补位）才转入 U09 的构成检查。
- 与 stm-employee-experience（U17）：本能力的委派=学习机会面向工作与成长；U17 面向入职到离职的体验触点与仪式设计。
- 与 stm-manager-role-lens（U07）："管理者业绩=成员的成果"的口径与职责清单属 U07 的总框架；本能力承接其中"自我转型怎么落地"的可执行路径（时间审计四桶）。
- 与 stm-mechanism-design（U15）：本能力只提出"用机制减少自己的工作"这一目标与判停检验；具体机制选型与设计流程（简报、同事奖金、倒推法）归 U15。

## E（可执行步骤）

1. **时间审计：列出当前所做工作**。记录（或回溯）一到两周内自己实际执行的全部工作，逐项写明：任务、每周耗时、是否本团队日常、是否只有你能做。完成标准：得到一份任务清单，每项含周耗时（小时）与"谁还能做"初判；无记录凭记忆估算时标注"估算"。

2. **四桶分类**（判停点在本步末）。把每项任务归入：① 成员能学的 → 委派（附一句"这是学习机会"的说明；对新人说"试试看"，不说"对你还太早"）；② 可机制化的 → 自动化/模式化（固定流程、周期提醒、模板）；③ 可外包的 → 外包/众包（独立、可验收的业务，先评估保密与质量约束，评估不过退回①或④）；④ 必须自己做的 → 保留（1on1、考核反馈、不可代办的人事决策、上级团队工作）。**判停点：若"必须自己做"桶 > 50% 周工时，先检查是否把成员能学的活记成了"只有我能做"——重判一次再继续；确属超载则先扩人/调结构（转 U09 跨度核算），不硬做委派**。完成标准：四桶清单各就位，委派桶每项标注接手人与交接周次。

3. **执行委派循环**。按"学习价值"排序委派项（成员学到的越多越优先，而非越省事越优先）；交接时交代背景与完成标准而非步骤细节；预期新人可能花 3 倍时间，把纠错成本计入计划。完成标准：委派项全部有接手人；管理者重复性工作周耗时显著下降（对比第 1 步基线，留档）。

4. **腾出时间参与上级团队工作**。把第 2-3 步释放的时间转投同级管理者团队的事务（跨团队协作、本层级策划、自己的 OKR 与 20% 项目），并在团队内公开自己的新时间配置。完成标准：周历中本团队一线任务时段被上级团队工作与管理动作替换，且团队成员知晓遇到什么问题该找谁。

5. **缺席检验**。安排一段管理者完全不介入的时间（休假或专注日），观察团队是否照常交付；回来后只复盘"哪些事卡在等我"，将卡点回流第 2 步重新分桶。完成标准：得到"不在场运转率"记录（照常交付/卡住事项清单）；连续两轮卡点为零，转型判定完成。

6. **团伙化自检**（收尾一次性执行）。对照四问：我最近的沟通里有多少在自夸本团队/贬低其他团队？我是否只用"一起喝酒"式关系维系成员？我是否只提拔言听计从者？我运转团队的目的里有几条是"为了公司"而非"为了自己"？完成标准：四问有书面回答；任一问触发"是"，列出一条改正动作（如公开称赞其他团队一次）。

**输入契约**：必需 = 一到两周的任务清单（任务、周耗时）+ 团队成员名单及各自可承接能力的大致描述。可选 = 可用自动化工具、外包/众包预算与制度许可、公司对外包的保密合规要求。缺任务清单时先补记录再开工，不凭印象直接分类。

**输出契约**：四桶分类表（任务/周耗时/桶别/接手人或机制名）+ 委派计划（每项含交接周次与学习价值说明）+ 机制化与外包候选清单（外包项附保密/质量评估结论）+ 转型前后时间对比（本团队一线耗时 vs 上级团队与管理耗时）+ 两轮缺席检验记录 + 团伙化自检四问答案。

## B（边界）

**反场景（何时不用）**：
- 团队构成、招聘标准、跨度与流动性问题——归 stm-team-composition（U09），本能力只在"要减的工作需要人接"时与它衔接；
- 成员入职后的体验与仪式设计——归 stm-employee-experience（U17）；
- 具体机制（简报、同事奖金、二人组）的选型设计——归 stm-mechanism-design（U15），本能力只定义"减少自己的工作"这个目标；
- 一对一面谈怎么谈、反馈怎么给——归 1on1 与反馈能力（U03/U10），本能力只决定"为面谈留出时间"。

**书中警告的失败模式（含候选反例 id）**：
- 日式参与型管理者（ce-45）：与成员做同样工作、把成员当助理、认定"5 个人的活必须 5 个人干"——公司效率无法提高，培养不出下一代管理者，教练下场踢球；
- 孤狼式管理者（ce-46）：只经营自己的小团队、不参与同级协作——评价极低，且管理者的安全感本取决于上一级团队，缺位即断供；
- 团伙管理者（ce-50）：运转团队为了自己——爱自夸、爱抱怨、拉帮结伙、挖人创业，逐渐失去信赖，团伙式创业基本失败；
- 不空手来问的反面：成员什么都没做就来问"怎么办"，管理者无从判断也无从对外分享口碑信息。

**作者盲点/时代局限**（阶段 0 批判）：
- "整合型"依托的外部资源生态（成熟众包平台、高技能副业者、零报酬合作者）部分是谷歌与作者个人品牌语境的产物；普通团队面对预算审批、保密合规、外部质量管控，外包/众包的可替代面显著更窄；
- 谷歌结构参数（管理者参与同级团队、20% 规则、1on1 频率）为 2010 年代经验值，科层较强的组织里"参加上级团队工作"未必被制度允许，书中仅建议"代表团队与上司抗争、逐步实现"；
- 作者利益相关（前谷歌高管+培训师），案例自选样且几乎全成功、无失败复盘；"沃兹尼亚克是被推下去的第二只企鹅"属轶事考证，非史实定论；
- 对转型期风险着墨少：委派初期的出错成本（书中只说"也许花 3 倍时间"）在高压交付期可能不可承受，需自行设置回切预案。
