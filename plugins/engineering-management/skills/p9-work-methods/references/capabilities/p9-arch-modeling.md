# 架构建模三式（繁简/虚实/无有）

## R（原文摘引）

> "先归纳再演绎，即先从已实现的业务中定义新实体，再用新实体实现原功能，最后通过最复杂的场景进行完整模型的验证。"（第8章 8.1）

> "物理元素是客观存在的，所有抽象概念都应建立在物理元素的基础上。……如果以这些人为定义为基础，那么架构的根基就不稳定，就像盖房子使用塑料泡沫一样。"（第8章 8.1.1）

> "科学家模式虽然有效，但无法终结问题，只有数学家模式才能真正回答那些'虚'的问题。这也是埃隆·马斯克推崇的'第一性原理'。"（第8章 8.2）

> "资金保障系数＝（账户匡算余额 × 匡算准确率＋调拨资金 × 摩擦系数＋预测流入资金 × 预测准确率）/（预测流出资金 / 预测准确率）。"（第8章 8.2.3）

> "在构建任何架构之前，必须先确定其位置。一旦有了明确的位置，架构就有了存在的意义。"（第8章 8.3.1）

> "过程可以总结为选种、育苗、生长、开花和结果五个步骤。"（第8章 8.3.2）

> "架构的最终目标就是将位置和价值相连接。因为我处于这个位置，所以我能提供这个价值；因为我实现了这个价值，所以我配得上这个位置。"（第8章 8.3.1）

## I（解释）

第8章把应用类架构难题分三重挑战，各配一式解法，先归类再选式：

**繁——问题清楚、解法也有，但逻辑不清、异常复杂**（老系统乱麻、越接越乱）。式一"从繁到简"是先归纳再演绎：升维观察（全局或终局视角）后，用客观物理元素（不是策略规则这类人造概念）定义新实体，用新实体重新指代系统，把功能重组成"一横多纵"结构（横=实体，纵=功能，可嵌套），再拿最复杂的场景验证模型，最后主动收集需求集中批量交付，用一场显著胜利（20 天完成全年需求数量）改变认知。

**虚——问题清楚，解法不明**（降本/提效/优化类课题年年立项年年烂尾，"只有方向没有路径、只有期望没有行动、只有概念没有实质"）。式二"从虚到实"是第一性原理四步：回到根本（找绕不过去的基本事实，如"优化=实际与预期的偏差"）→ 形成理论公式（把课题量化，如导航效率=一致次数/总次数）→ 长出能力树（从公式推出系统能力与框架，人人可见差距与路径）→ 定义性能参数（能力量化挂钩成熟度）。科学家模式的假设-求证循环高效但无法终结问题，只有数学家模式（公理化理论体系）才能真正终结"虚"课题。

**无——问题本身不清楚**（有资源有技术没场景，担心被淘汰）。式三"从无到有"先用七见模型看清缺口（位置→问题→解法→逻辑→概念→故事→价值），再用五步生长法开辟新领域：选种（先找钉子再孕育锤子，四求找真问题）、育苗（系统化论述、写白皮书）、生长（原型验证、设计与实施分离）、开花（爆品思维、指标达标后转场景思维）、结果（指标质变锁赛道 + 生态闭环）。

三重挑战占架构师工作比重递减（繁最多、无最少），但创新性与前瞻性递增。

## A1（原书案例 / 合成演练）

**原书案例一：制药流程的从繁到简建模（worked_example，第8章 8.1，图 8-1）**。输入：领域繁多、定义混乱的制药系统。执行：跳出化学药/生物药/中成药用"药物"一词囊括全部；用物理元素定义实体"药物 = 药物成分 + 辅料 + 赋形剂"（而非药效、规格等抽象概念）；把中间体合成、细胞培养、药材炮制等各异叫法统一为"活性成分合成"，制药过程重组为原料准备、活性成分合成、纯化、制剂、质检 5 个功能，形成一横多纵结构（活性成分合成内部再嵌套"化合物"实体及其子功能）。结论：用阿司匹林片（成分定义 + 乙酰化反应）与中药青蒿素等最复杂场景验证模型成立——化繁为简还是做原来的事，只是更易理解、效率更高（教学案例，结果未说明）。

**原书案例二：集中批量交付，20 天完成全年需求（firsthand，第8章 8.1.3）**。输入：作者亲历，简洁架构落地后仅靠逐个项目无法改变各方认知。执行：收集未来 3 个月可能出现的所有需求，用简洁架构集中批量交付，发挥规模优势。结论：短短 20 天完成全年的业务需求数量，彻底改变所有人对技术架构的认知，以一场显著胜利捍卫架构声誉、平定乱局。

**原书案例三：资金保障系数公式与能力树推演（worked_example，第8章 8.2.3，图 8-2/8-3）**。输入："资金保障"这一虚课题——要以最少资金保障"一手交钱一手交货"，跨国企业几乎不可能精确计算每笔资金。执行：回归核心公式"资金保障系数 =（补充资金 + 流入资金）/ 流出资金"（理想为 1，实际难达 1 甚至 2、3）；逐步细化为工程公式"（账户匡算余额×匡算准确率 + 调拨资金×摩擦系数 + 预测流入资金×预测准确率）÷（预测流出资金÷预测准确率）"——预测流出准确率仅 90% 时分母放大 1/0.9，需多备约 12% 资金；摩擦系数取决于资金分布（分散小账户若不连通，每户都按最大流出备资）。据此长出能力树（账户余额匡算[银企直连/资金匡算/交易账本]、资金调拨[资金决策/直连清结算网络/掉期]、流入流出资金预测[小时级/天级]）与整体框架（资金保障服务 → 资金匡算/预测/定价/运营 → 资金调拨/账户管理）。结论：任何人都能找到实际与理论的差距、知道每项能力对目标的贡献（课题推演，未交代落地结果）。

**原书案例四：高德导航的优化效率公式（worked_example，第8章 8.2.1/8.2.2）**。输入："优化"这个虚课题。执行：回到根本——优化无非是实际与预期的偏差（预期路径按公里数/时长/红绿灯等口径，实际路径记录每次真实导航的路段、时长、公里数）；形成理论公式——导航效率 = 实际与预期一致的导航次数 ÷ 所有导航次数，用大量真实导航数据持续完善匹配（与 AI 训练拟合相似）。结论：抽象课题被量化为可运营指标（推演示例，未说明目标阈值）。

**原书案例五：渠道逐个接入 vs 渠道建模 + 接入 70 天到 3 天（worked_example，第8章 8.3.1）**。输入：业务不断要求接入新支付渠道。执行：低段位思路是看每个渠道的接入文档按要求发报文，结果只能说"接了 A、B、C 渠道"；高段位思路是对渠道建模（信用卡/钱包/线下支付，各自的交互模式与关键关注点）。结论：能说清理解了多少种渠道、接入效率多高、沉淀了哪些核心能力——信用卡渠道接入时间从 70 天缩短到 3 天，作为七见模型"解法"与"价值"两见的实例。

**原书案例六：Loom 以分享功能构建心智壁垒（reported_case，第8章 8.3.2）**。输入：截屏应用这个红海品类。执行：Loom 发现人们截屏的目的是分享，于是围绕分享构建闭环——分享给他人查看、使用报告、查阅反馈，并形成"要不要 Loom 一下"的日常用语心智（类比"百度一下"）。结论：用户一旦使用就难以更换，体现五步生长法"结果"阶段的指标质变 + 周边生态闭环（书中转述的公开案例）。

## A2（情境应用）

**触发场景**：
- 接手一个领域繁多、链路复杂、定义混乱、设计臃肿的老系统（或多方联调的老大难项目），要重构简化；
- 降本、提效、优化、业务保障这类"年年进规划、年年烂尾"的虚课题，今年终于要做实；
- 团队要开辟新领域或跟进新技术方向（如大模型落地），找不到合适的问题与切入点，担心"有技术没场景"；
- 渠道/场景/租户不断增加，逐个定制的接入模式撑不住了，要建模沉淀；
- 架构述职或规划答辩，需要讲清自己的位置、问题、理论与价值（七见叙事链）。

**语言信号**：
- 中文：化繁为简、系统重构、实体建模、奥卡姆剃刀、一横多纵、第一性原理、理论公式、能力树、性能参数、虚课题、做实、从零到一、新领域、找赛道、找场景、真问题
- 英文：simplify the architecture, entity modeling, first principles, capability tree, performance parameters, theoretical formula, zero to one, new territory, problem discovery, north star metric

**与相邻能力的区分**（初稿）：
- 与 p9-arch-mindset（第7章）：先做三心魔自检（心态与边界），再进本卡三式（求解操作）；本卡不处理完美主义/风险主义/单一主义的心态问题。
- 与 p9-arch-stability（第8章 8.4–8.6）：本卡只覆盖应用类三式（繁/虚/无）；风险类三式（高可用 E(X)、资防四式、风险兜底）归 arch-stability。归类时"服务不可用/资金损失/未知异常"关键词应路由到那边。
- 与 p9-domain-modeling（第3章四招）：那是代码与领域层的"找实体、理关系、划边界、定行为"；本式一"定义实体"发生在架构课题层（可含流程与组织语义），粒度更粗、面向重构叙事而非代码落地。
- 与 p9-tech-planning（第12章）：技术规划的目标-路径-里程碑以本式二的公式、能力树与性能参数为输入素材。

## E（可执行步骤）

**第 0 步 归类判别**：对当前课题问三句——①问题清楚、解法也有、但逻辑混乱复杂？→ 式一（繁）。②问题清楚、但解法不明、似乎永无止境？→ 式二（虚）。③问题本身不清楚、有资源技术但无场景？→ 式三（无）。完成标准：能一句话说清课题属于哪一重及判断依据。判停点：三问都答不清 → 先做式三的七见定位（步骤 12）再回来归类。

**式一 从繁到简（步骤 1–6）**：

1. **升维观察**：空间维度（点→线→面→体，全局思维）或时间维度（过去→现在→未来，终局思维）跳出细节审视问题。完成标准：能用一个简单概念把当前所有对象囊括（如用"药物"囊括化学药/生物药/中成药）。
2. **抓物理元素定义新实体**：实体必须用客观存在的物理元素描述（药物 = 药物成分 + 辅料 + 赋形剂），不得以策略、规则、协议等人造抽象为根基。完成标准：实体定义在评审中人人同解、无各执一词。
3. **重新指代**：用新实体指代系统中已存在的元素。完成标准：指代准确，且指代后系统描述更精准、清晰、易懂（实体好坏的最低标准；好实体满足奥卡姆剃刀并经受进化论筛选）。
4. **一横多纵重组功能**：横 = 实体（协调多个功能、作为整体对外提供服务），多纵 = 功能；结构可嵌套（某功能内部可再定义子实体与子功能）。完成标准：原有全部功能在新结构中找到位置；新场景接入只需在"一横"上做简单配置。
5. **以最复杂场景做验证**：挑最复杂、最多样的场景检验模型（制药模型用阿司匹林的乙酰化反应 + 中药青蒿素）。判停点：解释复杂场景时仍感复杂 → 未满足奥卡姆剃刀，回到步骤 2 重新定义实体。
6. **批量释放红利**：主动收集未来一段时间（如 3 个月）的全部需求，用简洁架构集中批量交付。完成标准：用一场显著胜利（书中实证：20 天完成全年需求数量）改变各方对架构的认知。

**式二 从虚到实（步骤 7–11）**：

7. **回到根本**：找到任何人回答该课题都绕不过去的最基本事实或假设——优化 = 实际与预期的偏差；定价 → 有哪几层价格、每层定价公式；降本 → 成本由哪几部分组成、各部分计算公式；风险 → 端到端链路是什么、怎么追溯还原与定义。完成标准：课题拆解到"自然知道接下来要干什么"。
8. **形成理论公式**：定义可量化的概念把课题公式化（导航效率 = 实际与预期一致的导航次数 ÷ 所有导航次数），并用实际数据验证公式。完成标准：公式有明确变量、单位与口径，且已有数据可回测。
9. **长出能力树**：从公式推出系统能力树与整体框架结构。完成标准：每项能力能指出它影响公式的哪个变量、贡献方向是什么——人人可找到实际与理论的差距。
10. **定义性能参数**：为各能力定义量化指标并挂钩目标成熟度（如导航的覆盖维度、场景数、准确率；发动机看排气量、芯片看纳米制程）。完成标准：有参数表，含当前值与目标值。
11. **排建设优先级**：优先做"容易解决且影响大"的问题，尽早兑现价值，启动"抽象到具体"的飞轮效应。完成标准：能力清单按 影响 × 难度 排序，第一名已开工。

**计算契约（资金保障系数，书中完整推导）**：简化式：资金保障系数 =（补充资金 + 流入资金）÷ 流出资金，理想值 = 1（实际中达到 1 很难，甚至 2、3 都难）。工程式：资金保障系数 =（账户匡算余额 × 匡算准确率 + 调拨资金 × 摩擦系数 + 预测流入资金 × 预测准确率）÷（预测流出资金 ÷ 预测准确率）。口径约定：①流出预测准确率 90% → 分母放大 1/0.9 ≈ 1.11，需多备约 12% 资金（原书"取上近似为 0.12，即 12%"的口径）；②流入资金与账户余额的准确率低，则分子相应打折；③摩擦系数取决于资金分布与账户连通性——分散小账户不连通时每户按最大可能流出备资（效率低）；连通但只能次日到账需提前备全天流出量，缩到小时级则只需备几小时资金；④金额为货币单位，各准确率与摩擦系数为无量纲比率，系数为无量纲值。系数取值口径原书未给出，需按业务数据标定。

**式三 从无到有（步骤 12–17）**：

12. **七见定位（诊断与叙事链）**：一见位置（绘制全局架构图，将自身作为整体，找到上下左右，向外延展直至客户/合作伙伴等外部实体；位置即"域"）→ 二见问题（建问题树逐层拆解，定义高段位的问题——问题越大架构价值越大）→ 三见解法（对问题对象建模而非逐个实现：渠道分信用卡/钱包/线下，而非逐个看文档发报文）→ 四见逻辑（解法背后的原理/公式/模型，最好建立一套理论）→ 五见概念（为逻辑起一个好名字，讲一次就被记住，形成影响力）→ 六见故事（名人轶事/场景效果/类比比喻/发展历史，让同事、老板、客户愿意讲）→ 七见价值（用具体指标与技术参数支撑，如渠道接入 70 天 → 3 天）。完成标准：七层各有一句话答案，且位置与价值互相印证。
13. **选种（定义真问题）**：先找钉子、再孕育锤子（万能锤子可遇不可求）；真问题 = 源自客户实际需求、客户愿意付费、并在成本/效率/风险/体验带来实质改变。四求找钉子：求新（新业务或业务新阶段的位置红利）、求通（多领域共同关注的通用问题，如核算/对账/合规都关注交易与资金）、求专（用极端要求倒逼新领域：准确率 99.99%、资金处理 7×24 实时）、求本（回归效能/效率/安全/成本基本诉求，如隐私计算）。完成标准：能指认付费方与改变维度。判停点：论证以"这项技术很热"开头或找不到愿意付费的业务方 → 种子不合格，回四求重选。
14. **育苗（确认科学解法）**：解法至少经过系统化论述（假设、推理、验证），努力形成专业理论并撰写白皮书，不靠运气；目标定为量的大幅提升与质的最终改变（可复用式二找真解法）。完成标准：白皮书级文档成稿。
15. **生长（建设核心能力）**：先原型验证——构建基础框架、走通体现核心理念的关键逻辑、确立架构原则并求广泛共识、对技术难题深入预研、在实际场景完整走通、确定核心指标（好指标既体现当前水平又牵引未来）；方案设计与实施严格分离，不因资源进度牺牲设计质量；区分预型（类 MVP，商业验证）与原型（技术验证），两轨独立互不阻塞。完成标准：原型走通 + 核心指标确定 + 架构原则有共识记录。
16. **开花（实现阶段价值）**：用爆品思维做小规模尝试验证；指标处于低水平时提升指标，达到一定水平后转向场景思维（彻底解决特定场景问题、真正创造价值）；先从容易解决的问题和场景开始建立正反馈。判停点：指标好看但找不到真实使用案例 → 未开花，回到场景思维补场景。
17. **结果（扩大整体影响力）**：核心技术指标有质的提升以威慑对手、锁定赛道；构建配套周边生态形成闭环（Loom：分享 + 使用报告 + 反馈 → "Loom 一下"心智）。完成标准：有竞对参照的指标质变 + 至少一项生态配套能力上线。遵循自然生长规律：既不急于求成，也不自满自足。

**输入契约**：式一必需 = 现有系统功能清单或领域描述 + 典型场景集（必须含最复杂场景，缺时向用户索要，不自行假定）；可选 = 未来需求池（步骤 6 用）。式二必需 = 课题陈述 + 可获得的实际数据（历史口径、账目、链路数据）；缺数据时公式只能列为待验证假设并标注。式三必需 = 业务/客户信息（谁付费、什么诉求、改变什么）+ 可用资源与团队规模；缺付费方信息时先完成四求再进育苗。

**输出契约**：式一 = 实体定义表（实体 = 物理元素组合 + 一句话定义）+ 一横多纵结构图 + 最复杂场景验证记录 + 批量交付计划。式二 = 理论公式（变量、单位、口径）+ 能力树（能力 → 公式变量映射）+ 性能参数表（当前值/目标值）+ 建设优先级排序。式三 = 七见叙事链（七层各一句）+ 真问题卡（付费方/改变维度/四求来源）+ 五步阶段计划（标明当前所处阶段与判停条件）。

**判停点汇总**：归类不清 → 先七见定位；式一步骤 5 验证失败 → 回步骤 2 重定义实体；式二找不到任何可验证的公式 → 课题可能"虚"在数据积累不足，先退回补数据采集与埋点；式三种子不合格（技术驱动/无付费方）→ 回四求重选，不得以"先做了再说"强行育苗。

## B（边界）

**反场景（何时不用）**：
- 风险类架构问题（服务不可用、资金损失、未知异常）→ 用 p9-arch-stability 的从上到下/从内到外/从前到后三式（8.4–8.6），不要拿应用类三式硬套；
- 代码与领域模型层的实体-关系-边界-行为设计 → 用 p9-domain-modeling 四招；
- 动笔前的心态问题（完美/风险/单一主义）→ 先过 p9-arch-mindset 自检；
- 一次性的小范围功能设计（无繁/虚/无特征）→ 不必动用三式，直接设计评审。

**书中警告的失败模式**：
- ce130 以人为抽象概念定义实体——用策略、规则、协议、药效规格等人造概念当实体根基，指代不稳、评审各执一词，"就像盖房子使用塑料泡沫"；
- ce131 虚课题年复一年一无所获——靠经验和灵感提优化点，同一课题连续多年出现在规划中、无公式无参数，年年烂尾；
- ce132 种子缺陷与"万能锤子"执念——先有技术再找场景（论证以"这项技术很热"开头），或选了非客户付费驱动的伪问题，新领域从起点注定失败；
- ce133 急功近利、方案与实施不分离——为资源和进度牺牲设计质量，设计文档未评审即排期开发、关键技术难点"边做边看"，项目早启动却落后于预期；
- ce134 指标思维不转向场景思维——只盯核心指标数字，指标达标但无真实场景应用，没人续投资源，缺正反馈的创新中途失血。

**作者盲点/边界**：
- 制药、资金保障、渠道接入等案例全部出自蚂蚁国际支付语境；能力树细项（图 8-2/8-3）部分依赖插图说明，移植时需按自身业务重推；
- "20 天完成全年需求"是作者亲历孤例，不可作为普遍交付预期，批量释放红利的前提是需求池可收集、场景同构度高；
- 七见/五步/四求等数字框架命名整齐，但原书未给出严格划分依据（阶段 0 批判指出"事后归纳"风险），使用时应按实际课题裁剪层数，不硬凑七层五步；
- 五见"概念命名=影响力甚至权力"的论述带强个人品牌与话语权色彩，在扁平组织或需要严格客观论证的场合应降权，以四见逻辑与七见价值为实、以五见六见为辅；
- 资金保障系数的准确率与摩擦系数取值口径原书未给，直接套用 12% 这类数值而无本组织数据标定，会制造虚假的"确定性"。
